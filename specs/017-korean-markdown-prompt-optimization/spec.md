## 1. 개요 및 배경 (Overview & Background)

### 📌 문제 현상 및 기술적 원인 분석
LLM(Qwen, Llama 등)이 생성한 한국어 답변 텍스트에서 `**"자극 느껴져요"**라는`, `**"효과는 그냥 일반 토너랑 비슷함"**이라고`와 같이 **볼드 강조 기호(`**`)가 파싱되지 않고 화면에 별표 그대로 노출되는 렌더링 결함**이 발생하고 있습니다.

이 현상은 CommonMark / GFM(GitHub Flavored Markdown) 사양의 **'Right-flanking Delimiter' 규칙**과 **한국어 교착어(조사 결합) 문법 구조의 충돌**로 인해 발생합니다:
1. **CommonMark Right-flanking 규칙**: 닫는 구분자(`**`) 바로 앞이 구두점(따옴표 `"`, 괄호 `)` 등)인 경우, 구분자 바로 뒤에는 반드시 **공백(whitespace)** 또는 **구두점(punctuation)**이 와야만 유효한 닫는 강조 태그로 인식됩니다.
2. **한국어 조사의 충돌**: 한국어는 큰따옴표 뒤에 조사(`라는`, `이라고`, `은`, `는`, `이`, `가` 등)가 공백 없이 결합합니다. 조사는 유니코드 문자(Alphanumeric / Word character)로 분류되므로, 마크다운 파서는 닫는 `**`를 강조 종료 태그가 아닌 **일반 텍스트 또는 여는 구분자**로 오인하여 볼드가 풀리고 원시 기호가 그대로 노출됩니다.

### 🎯 개선 목표
본 명세서는 **① LLM 프롬프트 지시사항 고도화(생성단 원천 예방)**, **② 파이프라인 정규화 및 클라이언트단 방어 필터(파싱단 보정)**, **③ 모든 프론트엔드(Streamlit, FastAPI 웹, PILOS 웹) 간 렌더링 일관성 보장**을 통해 한국어 마크다운 강조 표시 결함을 100% 근절하는 표준 규격을 정의합니다.

## Clarifications

### Session 2026-08-19
- Q: 한국어 마크다운 볼드(**) 렌더링 결함을 해결하기 위해 어떤 방어 아키텍처를 적용할까요? → A: 3계층 하이브리드 방어 (프롬프트 라벨링 규격화 + 파이프라인 정규식 자동 보정 + 프론트엔드 안전 렌더링)
- Q: 실시간 토큰 스트리밍 환경에서 마크다운 자동 정규화 필터의 적용 계층을 어떻게 구성할까요? → A: 이중 방어 적용 (파이프라인 스트림 어댑터 + 프론트엔드 마크다운 렌더러 진입 직전 정규화)
- Q: 정규화 필터(normalize_korean_markdown)의 변환 범위를 어떻게 설정할까요? → A: 선택적 스마트 보정 (**"..."**조사 등 파싱 깨짐 유발 패턴만 <strong> 또는 공백 보정하여 원본 마크다운 구조 최대한 보존)

## 2. User Scenarios & Testing *(mandatory)*

### User Story 1 - 고객 및 사용자의 깨끗한 한국어 강조 텍스트 경험 (Priority: P1) 🎯 MVP

사용자가 뷰티 화장품 및 시장 수급 질문을 입력하여 AI 답변을 수신할 때, 답변 내의 핵심 키워드, 고객 리뷰 인용구, 속성 평가 내용이 깨진 별표(`**`) 없이 깔끔한 볼드체(`<strong>`)와 인용구 스타일로 렌더링되어야 합니다.

**Why this priority**:
답변 내에 원시 마크다운 기호(`**"텍스트"**라는`)가 노출되는 것은 서비스의 완성도와 전문성을 저해하는 가장 직관적인 UI 결함입니다.

**Independent Test**:
- 실제 질문("식물나라 토너 자극성과 기능/효과 분석해줘") 실행 시, 생성된 응답 내 모든 볼드 및 인용구 표현에서 별표 노출 0건 및 정상 강조 서식 적용 여부를 검증합니다.

**Acceptance Scenarios**:
1. **Given** LLM이 리뷰 원문 인용구를 포함한 답변을 생성할 때, **When** 사용자가 화면을 확인할 때, **Then** `**"문장"**라는` 형태의 별표 노출이 전혀 없이, `**속성명:** "인용 문장"이라는 피드백` 또는 `<strong>"인용 문장"</strong>이라는` 형태로 완벽하게 렌더링된다.
2. **Given** LLM이 속성 항목별 요약 리스트를 출력할 때, **When** 불릿 리스트가 렌더링되면, **Then** `- **항목명:** 상세 설명` 구조로 표준 공백 규격을 준수하여 라벨이 100% 볼드 처리된다.

### User Story 2 - 프롬프트 엔지니어링 표준 지침 및 예시 템플릿 확립 (Priority: P1)

AI 서비스 엔지니어는 LLM 프롬프트 작성 시 한국어 마크다운 렌더러의 한계를 고려한 **마크다운 안전 생성 지침(Markdown Safety Guidelines)**을 프롬프트 시스템 메시지에 일관되게 주입하여 모델이 스스로 호환성 높은 텍스트를 생성하도록 유도합니다.

**Why this priority**:
후처리 정규식에만 의존하면 복잡한 중첩 구문에서 부작용이 발생할 수 있으므로, LLM 생성 단계에서 CommonMark 친화적 토큰 시퀀스를 출력하도록 통제하는 것이 가장 안전합니다.

**Independent Test**:
- vLLM 모델 게이트웨이 및 `oliview_core` 프롬프트에 안전 지침을 주입한 후 생성된 50개 테스트 벤치마크 문장에서 마크다운 파싱 오류율 0%를 달성합니다.

**Acceptance Scenarios**:
1. **Given** 챗봇 프롬프트 템플릿이 구성될 때, **When** LLM 시스템 지시어가 전달되면, **Then** "따옴표와 볼드 기호를 중첩하지 말 것(`**\"...\"**` 금지, `**라벨:** \"...\"` 권장)" 규칙이 명시적으로 포함된다.
2. **Given** 키워드 강조가 필요할 때, **When** 조사가 결합될 경우, **Then** 모델은 조사를 볼드 바깥에 두고 공백을 확보하거나 조사까지 볼드에 포함(`**성분은**` 또는 `**[성분]**은`)하여 안전한 패턴을 생성한다.

### User Story 3 - 파이프라인 및 프론트엔드 CJK 마크다운 호환성 필터 강화 (Priority: P2)

프론트엔드 웹 챗봇(PILOS `chat.js`, Oliview ChatB, Streamlit ChatA)은 LLM이 간혹 비표준 마크다운을 출력하더라도 브라우저 파서 단계에서 CJK 친화적 정규화(Auto-Sanitization)를 수행하여 사용자 화면에 절대 별표가 노출되지 않도록 안전 가드를 구축합니다.

**Why this priority**:
소형 경량화 모델(2B, 4B)은 시스템 프롬프트 지시를 완벽히 준수하지 못할 확률이 있으므로, 클라이언트 렌더링 직전의 다계층 방어망이 필수적입니다.

**Independent Test**:
- `chat.js` 및 `oliview_core.sanitizer`의 마크다운 후처리 함수에 의도적으로 `**"테스트"**라는` 문자열을 주입했을 때 `<strong>"테스트"</strong>라는` 또는 `**"테스트"** 라는`으로 자동 교정됨을 단위 테스트로 검증합니다.

**Acceptance Scenarios**:
1. **Given** 비표준 볼드 패턴(`**"..."**조사`)이 포함된 스트림 토큰이 전달될 때, **When** 렌더러가 마크다운을 변환하면, **Then** 안전 정규화 필터가 이를 가로채 유효한 HTML `<strong>` 태그로 변환한다.
2. **Given** 실시간 SSE 토큰 스트리밍 도중 불완전한 별표 토큰이 들어올 때, **When** 실시간 파싱이 수행되면, **Then** 브라우저 무한 루프나 깨짐 없이 부드럽게 강조 서식이 완성된다.

## 3. Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 LLM 답변 생성 프롬프트(`bteam/oliview_core/pipeline.py`, `common.py`, PILOS 프롬프트)에 한국어 CommonMark 호환 마크다운 작성 규칙을 필수로 포함해야 한다.
- **FR-002**: 프롬프트 규칙은 다음 3대 안전 문법을 엄격히 명시해야 한다:
  1. **인용구 볼드 중첩 금지**: `**"인용문"**라는` 형태의 작성을 금지하고, `**항목명:** "인용문"이라는 평가` 또는 단순 `"인용문"`으로 작성할 것.
  2. **구조화된 리스트 라벨링**: 속성 및 특징 분석 시 `- **라벨명:** 내용 설명` (콜론 뒤 공백 1칸 필수) 형식을 일관되게 사용할 것.
  3. **조사 결합 안전 처리**: 단어 강조 시 조사를 포함하여 볼드 처리(`**피부톤은**`)하거나 대괄호 표기(`**[수분감]**`)를 권장할 것.
- **FR-003**: `bteam/oliview_core/sanitizer.py`에 CJK 마크다운 정규화 유틸리티(`normalize_korean_markdown()`)를 신설하여, LLM 응답 텍스트 내의 비정상 볼드 패턴(`\*\*["'](.+?)["']\*\*([가-힣]+)`)을 파서가 인식 가능한 표준 문법(`<strong>"$1"</strong>$2` 또는 공백 보정)으로 자동 전처리해야 한다.
- **FR-004**: PILOS 웹 챗봇의 `pilos/web/static/js/chat.js` 및 Oliview ChatB의 마크다운 렌더러에 한국어 조사 결합 볼드 패턴 자동 변환 정규식을 적용하여 브라우저 렌더링 무결성을 보장해야 한다.
- **FR-005**: 챗봇 A(Streamlit)의 메인 뷰어에서도 LLM 스트리밍 출력 전후로 정규화 필터를 거쳐 Streamlit 네이티브 마크다운 렌더러에서 볼드가 100% 정상 적용되도록 해야 한다.

---

### Key Entities

- **MarkdownPromptTemplate**: LLM에게 마크다운 포맷팅 가이드라인(인용구 분리, 리스트 라벨링, 조사 처리)을 강제하는 표준 프롬프트 모듈.
- **KoreanMarkdownSanitizer**: 한국어 교착어 특성으로 인해 발생하는 CommonMark Right-flanking 파싱 오류(`**"..."**조사`)를 감지하여 HTML `<strong>` 또는 유효 마크다운으로 치환하는 정규화 유틸리티.

## 4. Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: **한국어 마크다운 별표 노출 결함율 0%** - 100회 이상의 질문 테스트(스킨케어, 클렌징, 립 등 다양한 화장품 질문)에서 `**"텍스트"**라는` 형태의 마크다운 원시 기호 노출 빈도가 0건이어야 한다.
- **SC-002**: **속성 분석 가독성 100% 달성** - 모든 챗봇 응답의 장단점 및 리뷰 인용구가 `- **라벨명:** "인용문" 설명` 형태로 균일하게 정돈되어 시각적 정보 전달력이 향상된다.
- **SC-003**: **정규화 처리 오버헤드 1ms 미만** - 마크다운 텍스트 정규화 처리가 전체 스트리밍 및 응답 생성 속도에 미치는 지연 시간이 1ms 미만이어야 한다.
- **SC-004**: **크로스 프론트엔드 렌더링 일관성 100%** - ChatA(Streamlit), ChatB(FastAPI/VanillaJS), PILOS(Flask/VanillaJS) 3개 프론트엔드 모두에서 동일한 마크다운 응답이 시각적 결함 없이 일관되게 렌더링되어야 한다.

## 5. Assumptions

- **A-001**: Streamlit, GFM, marked.js, vanilla JS 파서 등 브라우저 환경에서 동작하는 마크다운 렌더러는 기본적으로 CommonMark 표준 사양을 따른다.
- **A-002**: LLM 모델(Qwen3.5-4b 등)은 명확한 Few-Shot 예시와 시스템 가이드라인이 주어졌을 때 지시된 마크다운 구조(`- **라벨:** "인용구"`)를 높은 확률로 준수한다.
