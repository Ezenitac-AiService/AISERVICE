## 1. 개요 및 문제 분석 (Overview & Problem Analysis)

### 1.1 현상 분석 (Observed Failure Case)
사용자가 `"헤라 센슈얼 립 촉촉함과 각질부각 분석해줘"`를 입력했을 때 ChatA에서 다음과 같은 심각한 품질 결함이 관측되었습니다:
1. **0건 선별 및 출처 아코디언 미노출**:
   - 상태 헤더에 `✅ 분석 완료 (18.1초)`만 표시되고 선별 건수가 누락되었으며, 하단 `📚 참조 리뷰 원문` 아코디언이 전혀 렌더링되지 않음.
2. **시리즈/라인명 모호성 해소 실패 (Catalog Resolution Failure)**:
   - "헤라 센슈얼 립"은 특정 단일 상품명이 아니라 라인명("센슈얼 누드 밤", "센슈얼 누드 글로스", "센슈얼 피팅 글로우 틴트" 등)임에도 단일 상품으로 오인되어 정확한 상품을 찾지 못함.
3. **완전한 가짜 후기 환각 (Hallucination)**:
   - 본문 내 실제 리뷰 인용 번호(`[리뷰 1]`, `[리뷰 2]`)가 단 하나도 포함되지 않음.
   - LLM이 임의로 `"입술이 너무 젖어 마르지 않는 느낌"`, `"한 번에 여러 개를 문질러서 색상이 변조"`, `"입술이 마르지 않는 것"` 등 비현실적인 문장을 지어냄.
4. **뷰티 도메인 부정 속성어 왜곡 (Domain Aspect Semantic Distortion)**:
   - 사용자가 질문한 `"각질부각"`은 화장품 도메인에서 "각질이 도드라져 보이는 부정적 단점(Flaking/Accentuation)"을 의미함에도, LLM이 `"각질부각 효과: 거친 각질을 부드럽게 해주는 데 도움이 된 것 같다"`라며 긍정적인 각질 완화 효과로 정반대로 왜곡함.
5. **모바일 반응형 최적화 필요**:
   - Streamlit의 기본 레이아웃은 모바일 화면에서 상단 2열이 세로로 길게 늘어져 실제 채팅 영역에 도달하기 위해 많은 스크롤이 필요함.

### 1.2 목표 (Goals)
1. **시리즈/라인명 부분 일치 자동 확장 (Series/Sub-brand Resolution)**: "헤라 센슈얼", "롬앤 쥬시" 등 시리즈명 입력 시 카탈로그에서 해당 라인의 대표 실존 상품 2~3종을 자동 매칭하여 리뷰를 확보하고 비교 요약 제공.
2. **화장품 부정 속성 사전(Cosmetic Negative Aspect Lexicon) 구축**: "각질부각", "요철부각", "들뜸", "밀림", "다크닝", "뭉침", "가루날림" 등의 부정 속성어를 프롬프트와 가드레일에서 명확히 단점/주의점으로 고정.
3. **리뷰 0건 시 하드 블록(Hard Block) 및 제로 서치 템플릿 강제**: 실제 리뷰가 없을 때 LLM에게 "만족스러운 점/아쉬운 점" 작성을 일절 허용하지 않고 즉시 스펙 안내 및 부재 고지 출력.
4. **인라인 인용 부호(`[리뷰 N]`) 누락 시 자동 보정 및 엄격 검증**.
5. **ChatA FastAPI Web 전환 & 데스크탑 동일 레이아웃 + 2026 모바일 반응형 웹(Responsive Web)**:
   - 데스크탑($\ge 768\text{px}$): 기존 ChatA의 2열 레이아웃, 브랜드/속성 칩, 1클릭 질문 예시, 하단 블러 고정 바를 100% 동일하게 재현.
   - 모바일($< 768\text{px}$): 2026 트렌드인 **엄지손가락 영역(Thumb-Zone)**, **가로 스크롤 칩 필터**, **참조 리뷰 바텀 시트(Bottom Sheet)** 및 스마트 하단 입력창을 적용하여 모바일 UX 극대화.

### Session 2026-08-26

- **Q: ChatA(Streamlit) 및 ChatB에서 구형 레거시 파이프라인(prepare_pipeline_stream)을 완전히 정리하고, 신규 LangGraph 단일 엔진으로 전면 일원화할까요?** → **A: Option A 확정. 레거시 파이프라인 분기를 완전 정리하고 LangGraph 단일 파이프라인(MultiTargetGraphOrchestrator)으로 전면 일원화하여 가드레일, 제로 서치, 인용 일치성을 단일 엔진에서 100% 보장하도록 확정함.**
- **Q: ChatA의 웹 프레임워크 교체 시 데스크탑과 모바일의 반응형 레이아웃 정책을 어떻게 수립할까요?** → **A: 확정. 데스크탑 모드에서는 기존 2열 레이아웃(브랜드/카테고리/속성 칩 + 1클릭 질문 예시)을 100% 동일(Pixel-Identical)하게 유지하고, 모바일 모드에서는 2026 웹 트렌드(가로 스크롤 칩 바, Thumb-Zone 입력창, 참조 리뷰 바텀 시트 Drawer, Safe-Area 대응)를 적용한 모바일 최적화 반응형 레이아웃을 제공함.**

## 3. User Scenarios & Testing *(mandatory)*

### User Story 1 - 라인/시리즈명 및 약칭 질의의 실존 상품 자동 매칭 및 리뷰 인용 (Priority: P1) 🎯 MVP

사용자가 특정 세부 상품명이 아닌 라인명이나 시리즈 약칭(예: "헤라 센슈얼 립", "차앤박 프로폴리스", "롬앤 쥬시 틴트")으로 질문하더라도, 시스템은 카탈로그 내 해당 라인의 실존 대표 상품 2~3종을 정확히 찾아 실제 리뷰를 수집하고 `[제품명A 리뷰 1]`, `[제품명B 리뷰 1]` 인용과 함께 제품별 비교 요약을 제공해야 합니다.

- **Why this priority**: 소비자의 대다수는 전체 상품 풀네임 대신 시리즈 약칭으로 질문하며, 실존 상품 리뷰와 인용 부호가 정확히 제공되어야 신뢰할 수 있기 때문입니다.
- **Independent Test**: "헤라 센슈얼 립 촉촉함과 각질부각 분석해줘" 질의 시, "헤라 센슈얼 누드 밤", "헤라 센슈얼 누드 글로스" 등 실존 상품 2종 이상이 매칭되어 실제 리뷰 3건 이상이 확보되고, 본문에 `[헤라 센슈얼 누드 밤 리뷰 1]` 등의 인용이 정확히 표기되며 하단에 원문 아코디언이 펼쳐지는지 검증.

**Acceptance Scenarios**:
1. **Given** 라인명 약칭(예: "헤라 센슈얼 립")이 입력되었을 때, **When** 카탈로그 조회가 실행되면, **Then** `brand="헤라"`, `query="센슈얼"` 서브스트링 매칭으로 실존 상품 2~3종을 자동 인출하고 각 상품별 리뷰를 성공적으로 수집해야 한다.
2. **Given** 수집된 실제 리뷰가 존재할 때, **When** 답변이 생성되면, **Then** 모든 장단점 서술에 최소 1개 이상의 인용 태그가 포함되어야 하며, 하단 `📚 참조 리뷰 원문`에 동일한 리뷰가 노출되어야 한다.

### User Story 2 - 화장품 도메인 부정 속성어("각질부각", "요철부각", "다크닝") 의미 왜곡 방지 (Priority: P2)

사용자가 "각질부각", "요철부각", "들뜸", "밀림", "다크닝" 등 화장품 단점 속성에 대해 질문할 때, 시스템은 이를 '부정적 현상의 발생 여부'로 정확히 이해하고 장점으로 왜곡하지 않고 균형 있게 분석해야 합니다.

- **Why this priority**: "각질부각 효과가 좋다"와 같은 엉터리 답변은 뷰티 전문 AI로서의 전문성과 신뢰도를 심각하게 훼손하기 때문입니다.
- **Independent Test**: "각질부각 어때?" 질의 시, "각질이 부각되는지(도드라지는지) 여부"로 해석하여 리뷰 내 건조함/각질 부각 관련 부정/긍정 의견을 아쉬운 점 또는 장점 영역에 올바르게 배치하는지 검증.

**Acceptance Scenarios**:
1. **Given** "각질부각", "요철부각", "다크닝" 등의 부정 속성어가 포함된 질의가 입력되었을 때, **When** 프롬프트 및 의도 분석이 수행되면, **Then** 해당 단어를 '부정적 단점 발생 여부'로 분류하여 시스템 프롬프트에 주입해야 한다.
2. **Given** 생성된 답변을 검증할 때, **When** "각질부각 효과"와 같이 부정 속성을 긍정 효과로 잘못 기술한 문장이 감지되면, **Then** 가드레일이 이를 "각질 부각 여부"로 정정해야 한다.

### User Story 3 - ChatA FastAPI 웹 전환 및 Pixel-Identical 데스크탑 UI 계승 (Priority: P3)

ChatA 웹 인터페이스를 FastAPI 백엔드 기반의 모던 웹앱으로 전환하되, 기존 Streamlit ChatA의 시각적 디자인(상단 브랜드/카테고리/속성 2열 박스, 1클릭 질문 예시, 하단 고정 입력창, 상태 박스)을 100% 동일하게 유지하여 사용자가 프레임워크 교체를 체감하지 못하도록 하면서 즉각 중단(Stop) 및 부드러운 스트리밍을 제공해야 합니다.

- **Why this priority**: 전사 백엔드 아키텍처를 FastAPI로 일원화하고, Streamlit의 전체 Re-run 및 스트리밍 중단 한계를 완벽히 극복하기 위함입니다.
- **Independent Test**: 웹 브라우저에서 ChatA 접속 시 기존과 완전히 동일한 UI 화면이 표시되며, 질문 입력 시 0ms 즉각 타이핑 스트리밍 및 '생성 중단' 클릭 시 즉시 중단되는지 검증.

**Acceptance Scenarios**:
1. **Given** 사용자가 데스크탑 웹 브라우저에서 ChatA에 접속했을 때, **When** 화면을 확인하면, **Then** 기존 Streamlit ChatA와 동일한 상단 브랜드 칩, 카테고리 선택 버튼, 속성 칩, 질문 예시 버튼 및 하단 블러 고정 입력창이 100% 동일한 레이아웃으로 표시되어야 한다.
2. **Given** 스트리밍 답변 생성이 진행 중일 때, **When** 사용자가 입력창 옆 '생성 중단(⏹️)' 버튼을 누르면, **Then** `AbortController`를 통해 즉시 스트림이 멈추고 서버 리소스가 반환되어야 한다.

### User Story 4 - 2026 모바일 최적화 반응형 웹(Responsive Web) 레이아웃 지원 (Priority: P4)

스마트폰 및 태블릿으로 접속한 사용자에게 2026년 모바일 UX 트렌드에 최적화된 엄지손가락 중심(Thumb-Zone), 가로 스크롤 카테고리 칩 바, 참조 리뷰 바텀 시트(Bottom Sheet) 인터랙션을 제공해야 합니다.

- **Why this priority**: 모바일 사용자가 전체의 60% 이상을 차지하므로, 데스크탑 2열 구조를 모바일 1열 흐름과 바텀 시트로 최적화해야 이탈률을 낮출 수 있습니다.
- **Independent Test**: 모바일 뷰포트(375px~430px)로 접속 시 상단 가로 스크롤 칩과 하단 고정 입력창이 스마트하게 배치되고, 본문의 `[리뷰 N]` 클릭 시 하단 바텀 시트 드로어가 부드럽게 올라오는지 검증.

**Acceptance Scenarios**:
1. **Given** 모바일 뷰포트(< 768px)에서 접속했을 때, **When** 화면을 스크롤하면, **Then** 상단 분석 설정이 가로 스크롤 칩 필터로 컴팩트하게 전환되어 채팅 메시지 영역이 화면의 70% 이상을 차지해야 한다.
2. **Given** 모바일에서 본문의 `[리뷰 1]` 인용 태그를 터치했을 때, **When** 사용자가 탭하면, **Then** 하단에서 반투명 오버레이와 함께 '참조 리뷰 원문 바텀 시트'가 부드럽게 슬라이드업되어야 한다.

## 4. Edge Cases

- **EC-001 (동일 브랜드 내 다수 시리즈 존재)**: "헤라 립" 질의 시 "헤라 센슈얼 누드 밤", "헤라 센슈얼 피팅 글로우 틴트" 등 다수 제품이 검색될 경우 상위 평점/리뷰수 기준 2~3종을 선별하여 다중 타겟 비교 형태로 제공.
- **EC-002 (속성어와 품목명의 중복)**: "립밤 각질부각" 질의 시 "립밤"을 카테고리로, "각질부각"을 부정 속성어로 정확히 분리.
- **EC-003 (모바일 가상 키보드 팝업 시 레이아웃 깨짐)**: 모바일 브라우저에서 가상 키보드가 올라올 때 `visualViewport` API 및 `env(safe-area-inset-bottom)`을 통해 입력창이 가려지지 않고 키보드 상단에 정확히 밀착 유지.
- **EC-004 (네트워크 단절 및 백엔드 에러)**: SSE 스트리밍 도중 연결 단절 시 재시도 안내 및 정직한 에러 토스트 표시.

## 5. Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (시리즈/부분명 퍼지 카탈로그 매칭)**: 질의 정규화 엔진은 입력된 상품명이 단일 완제품과 100% 일치하지 않더라도 브랜드명과 핵심 키워드(예: `헤라` + `센슈얼`)를 조합한 서브스트링 검색으로 상위 매칭 상품 2~3종을 자동 인출해야 한다.
- **FR-002 (뷰티 부정 속성 사전 구축)**: 시스템은 `각질부각`, `요철부각`, `들뜸`, `밀림`, `다크닝`, `뭉침`, `가루날림`, `건조함`, `번짐`을 `NEGATIVE_ASPECT_TERMS`로 정의하고 프롬프트에 "부정적 단점 발생 여부로 해석할 것"을 명시해야 한다.
- **FR-003 (인라인 인용 부호 강제 주입)**: 실제 리뷰가 1건 이상 존재하는 모든 분석 답변은 각 주장/속성 문장 끝에 반드시 `[리뷰 N]` (비교 시 `[제품명 리뷰 N]`) 인라인 태그를 포함해야 한다.
- **FR-004 (인용 태그 누락 감지 및 재시도/보정)**: 생성된 답변 본문에 `[리뷰 N]` 태그가 전무할 경우, 후처리 가드레일이 선별된 리뷰 번호를 기반으로 적절한 인용을 자동 삽입하거나 검증 실패를 처리해야 한다.
- **FR-005 (제로 서치 하드 블록)**: RAG 파이프라인에서 선별된 리뷰가 0건일 경우, 자유 서술형 LLM 프롬프트를 완전 차단하고 `ZERO_SEARCH_TEMPLATE`을 확정 렌더링해야 한다.
- **FR-006 (UI 상태 카운트 투명 표시)**: UI는 상태 박스에 반드시 선별된 리뷰 건수(예: `✅ 리뷰 분석 완료 (1.2초, 4건 선별)`)를 투명하게 표시해야 한다.
- **FR-007 (LangGraph 단일 엔진 일원화)**: ChatA 및 ChatB는 구형 이중 분기(`prepare_pipeline_stream`)를 완전 제거하고 `MultiTargetGraphOrchestrator` 기반의 단일 LangGraph 엔진으로 전면 일원화해야 한다.
- **FR-008 (ChatA FastAPI Web 전환 및 Pixel-Identical 디자인)**: ChatA를 FastAPI 정적 서빙 및 SSE 스트리밍 웹앱(`index.html`, `style.css`, `app.js`)으로 구현하되, 데스크탑($\ge 768\text{px}$) 환경에서는 기존 Streamlit ChatA의 2열 레이아웃, 컬러 팔레트, 폰트, 상태 박스, 하단 고정 입력창 및 1클릭 질문 예시를 100% 동일하게 재현해야 한다.
- **FR-009 (2026 모바일 반응형 웹 & 바텀 시트 지원)**: 시스템은 미디어 쿼리(`@media (max-width: 768px)`)를 통해 모바일 환경에서 가로 스크롤 칩 필터, Thumb-Zone 하단 고정 바, `[리뷰 N]` 탭 시 슬라이드업되는 **바텀 시트 드로어(Bottom Sheet Drawer)** 및 모바일 Safe-Area(`env(safe-area-inset-bottom)`)를 완벽히 지원해야 한다.

## 6. Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 (시리즈명 질의 리뷰 수집 성공률)**: "헤라 센슈얼 립", "차앤박 프로폴리스" 등 시리즈명 질의 시 실존 상품 매칭 및 리뷰 수집 성공률이 95% 이상이어야 한다.
- **SC-002 (인용 표기 누락률 0%)**: 리뷰가 존재하는 정상 답변에서 `[리뷰 N]` 인라인 인용 부호 누락률이 0%여야 한다.
- **SC-003 (부정 속성어 왜곡 발생률 0%)**: "각질부각" 등의 단어가 긍정적 효과("각질부각 효과가 좋다")로 오역되는 발생률이 0%여야 한다.
- **SC-004 (가짜 리뷰 환각 발생률 0%)**: 0건 리뷰 시 임의의 가짜 인용문("안녕하세요? 순하고", "입술이 너무 젖음") 생성률이 0%여야 한다.
- **SC-005 (데스크탑 UI 레이아웃 일치성 100%)**: 신규 FastAPI 웹 클라이언트가 데스크탑 환경에서 기존 ChatA와 시각적 요소(컬러, 폰트, 2열 배치, 버튼 구성) 100% 동일함을 보장한다.
- **SC-006 (즉시 중단 반응 속도)**: '생성 중단' 클릭 시 100ms 이내에 클라이언트 렌더링이 멈추고 서버 연결이 종료된다.
- **SC-007 (모바일 반응형 적합성 100%)**: 모바일 뷰포트(375px~430px)에서 가로 스크롤 깨짐, 키보드 가림, 하단 입력창 잘림 현상이 0건이어야 한다.
