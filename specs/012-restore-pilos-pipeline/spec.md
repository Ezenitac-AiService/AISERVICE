## 개요 및 배경 (Overview & Context)

Pilos 주식 분석 서비스는 KOSPI 주요 10개 종목을 대상으로 투자자 여론 댓글 데이터 수집, 감성 지수 산출, 수급 데이터 연동 및 AI 시장 해설 보고서를 매일 생성하여 투자자에게 제공하는 서비스입니다.

현재 데이터 수집 파이프라인의 동작이 중단되어 새로운 투자자 댓글과 수급 데이터가 반영되지 않고 있으며, 특히 2026년 8월 12일 이후부터의 감성 분석 지표 산출과 AI 시장 해설 보고서 생성이 누락되어 있습니다. 이로 인해 사용자가 웹 대시보드에서 최신 일자(8월 12일 이후)를 조회할 때 최신 분석 자료와 시장 해설 보고서를 확인할 수 없는 상태입니다.

본 기능 명세는 중단된 파이프라인의 근본 원인을 명확히 규명하고 재발 방지 대책을 수립하며, 8월 12일부터 현재까지의 누락된 데이터 수집 및 분석 보고서를 소급 생성(Backfill)하여 서비스의 연속성과 최신성을 영구 보장하는 것을 목표로 합니다. 아울러 GPU VRAM을 4GB 이하로 쾌적하게 유지하기 위해 통합 LLM 서빙의 기본 모델을 경량 모델(`qwen3.5-2b`)로 최적화 전환합니다.

## 원인 분석 및 시스템 진단 (Root Cause Analysis & System Diagnosis)

### 1. 파이프라인 중단 근본 원인 (Root Cause)
1. **수급 데이터 수집 단계(`supply_demand`)의 치명적 예외 발생**:
   - `pilos-worker`는 `[댓글수집 -> 전처리 -> 토큰화 -> 일별문서 -> 수급수집 -> 모델추론 -> LLM보고서]` 7단계를 순차 실행합니다.
   - 키움증권 수급 수집 모듈(`collect_supply_demand.py`) 실행 시 API 인증 키(`KIWOOM_APP_KEY`, `KIWOOM_SECRET_KEY`)가 설정되지 않은 환경에서 `ValueError: 키움 App Key와 Secret Key가 필요합니다.` 예외가 발생했습니다.
2. **후속 핵심 AI 파이프라인 연쇄 중단 (Cascading Pipeline Failure)**:
   - 5단계(`supply_demand`)에서 발생한 예외로 인해 최상위 실행기(`run_service_pipeline.py`)가 즉시 `failed` 상태로 종료되었습니다.
   - 이로 인해 댓글 수집·전처리는 매 주기마다 정상 실행되어 DB에 8월 19일까지 적재되었으나, **6단계(Ridge 감성 모델 추론 `model_inference`) 및 7단계(AI 시장 해설 보고서 생성 `llm_report`)가 8월 12일 이후 단 한 번도 실행되지 못하는 현상**이 발생했습니다.
3. **외부 종속성에 대한 결함 허용(Fault Tolerance) 부재**:
   - 외부 금융 API 키 부재나 일시 장애와 같은 부가적 수급 데이터 수집 실패가 핵심 서비스인 감성 분석 및 AI 보고서 생성 전체를 블로킹하는 취약한 결합 구조가 원인이었습니다.

### 2. GPU VRAM 점유 및 LLM 서빙 서버 진단 & 경량화 방침
- **진단 결과**: LLM 서버(`vllm-serv-gateway`)는 정상 가동 중(200 OK)이었으나, 4B 모델(`qwen3.5-4b`) 상주 및 Windows 호스트 UI 점유로 인해 총 VRAM 점유량이 7.8GB에 달했습니다.
- **경량화 결정**: GPU VRAM 사용량을 4GB 이하(순수 LLM 2.8~3.0GB)로 여유 있게 통제하기 위해, 기본 서빙 모델을 **경량 모델(`qwen3.5-2b`)**로 전환하여 메모리 안정성을 확보합니다.

### 3. 재발 방지 대책 (Prevention Strategy)
1. **외부 API 미설정/장애 시 우아한 스킵(Graceful Fallback)**:
   - 외부 수급 API 키가 설정되지 않았거나 호출이 실패할 경우, 파이프라인 전체를 에러로 중단하지 않고 `SKIPPED (NO_CREDENTIALS)` 상태로 정상 기록한 뒤 후속 모델 추론 및 보고서 생성 단계로 안전하게 진행합니다.
2. **단계별 격리 및 복원력 강화 (Stage Resilience)**:
   - 비핵심 부가 데이터 단계의 실패가 핵심 감성 지수 산출 및 LLM 시장 해설 보고서 생성 파이프라인을 차단하지 못하도록 단계 간 독립성을 보장합니다.
3. **누락 구간(8월 12일~현재) 전수 소급 복구(Backfill)**:
   - 이미 수집·전처리되어 있는 8월 12일부터 현재까지의 일별 데이터에 대해 감성 지표 추론 및 LLM 보고서 생성을 전수 일괄 실행하여 데이터 공백을 즉시 해소합니다.
4. **LLM 경량 서빙 기본화 (`qwen3.5-2b`)**:
   - VRAM 점유를 대폭 낮추고 보고서 생성 속도를 가속화하여 장기적인 서비스 안정성을 확보합니다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 최신 일자(8월 12일 이후) 주식 분석 보고서 및 감성 지표 조회 (Priority: P1)

투자자는 Pilos 주식 분석 웹 화면에서 종목(예: 현대차, SK하이닉스 등)을 선택하고 2026년 8월 12일 이후의 최근 거래 일자를 조회했을 때, 누락이나 대기 상태 없이 완전한 시장 해설 보고서와 감성 지수를 확인할 수 있어야 합니다.

**Why this priority**: 투자자에게 최신 시장 심리와 분석 정보를 실시간으로 제공하는 것이 서비스의 핵심 가치이며, 현재 데이터 공백으로 인해 서비스 본연의 기능을 수행하지 못하고 있기 때문입니다.

**Independent Test**:
- 웹 대시보드에서 10개 대상 종목 중 임의의 종목을 선택합니다.
- 날짜 선택기에서 2026년 8월 12일 이후부터 최근 거래일까지의 일자를 순차적으로 선택합니다.
- 각 일자별로 AI 시장 해설 본문, 수급 방향성, 신호 점수 및 감성 지표가 정상적으로 표시되는지 검증합니다.

**Acceptance Scenarios**:
1. **Given** 2026년 8월 12일부터 현재 사이의 유효 거래일과 대상 종목이 주어졌을 때, **When** 사용자가 해당 일자의 종목 상세 화면을 조회하면, **Then** 시스템은 빈 화면이나 대기 메시지 없이 완전한 시장 해설 요약 및 지표를 표시한다.
2. **Given** 8월 12일 이후 누락되었던 기간의 데이터가 주어졌을 때, **When** 보고서 조회 요청이 발생하면, **Then** 시스템은 성공 응답(200 OK)과 함께 파싱된 보고서 콘텐츠를 반환한다.

### User Story 2 - 자동 데이터 수집 및 분석 파이프라인의 주기적 정상 실행 (Priority: P2)

서비스 운영자는 백그라운드 파이프라인이 정해진 주기(10분)마다 자동으로 실행되어 신규 투자자 댓글 수집부터 텍스트 전처리, 일별 문서 생성, 수급 데이터 동기화, 감성 모델 분석, AI 시장 해설 보고서 생성에 이르는 전 과정을 끊김 없이 완수하기를 원합니다.

**Why this priority**: 데이터 수집과 보고서 생성이 사람의 수동 개입 없이 자동으로 유지되어야 지속 가능한 서비스 운영이 가능하기 때문입니다.

**Independent Test**:
- 백그라운드 파이프라인 스케줄러를 가동하고 지정된 주기(10분) 동안 대기합니다.
- 신규 댓글 수집과 함께 이후 분석 단계들이 순차적으로 자동 실행되어 완료 상태로 기록되는지 확인합니다.

**Acceptance Scenarios**:
1. **Given** 서비스 파이프라인 스케줄러가 활성화된 상태일 때, **When** 정기 실행 시점이 도래하면, **Then** 시스템은 수집부터 보고서 생성까지의 단계를 순차적으로 실행하고 결과를 정상 완료 상태로 기록한다.
2. **Given** 외부 수급 API 키가 설정되지 않은 환경일 때, **When** 파이프라인이 실행되면, **Then** 수급 수집 단계는 안전하게 스킵되고 후속 모델 추론 및 LLM 보고서 생성이 성공적으로 완료된다.
3. **Given** 선행 수집 또는 분석 작업이 실행 중일 때, **When** 다음 주기 실행이 트리거되면, **Then** 시스템은 중복 실행으로 인한 충돌이나 교착 상태(Deadlock) 없이 안전하게 다음 주기로 조율한다.

### User Story 3 - 파이프라인 장애 감지 및 소급 복구(Backfill) 메커니즘 (Priority: P3)

시스템 관리자는 8월 12일부터 현재까지 누락된 구간을 감지하고, 소급 복구 프로세스를 통해 10개 대상 종목 전체의 과거 미생성 일별 문서 및 최종 AI 보고서를 일괄 생성할 수 있어야 합니다.

**Why this priority**: 일시적인 네트워크 장애나 외부 서비스 중단 후에도 과거 누락 데이터를 완전하게 메워 데이터 정합성을 유지해야 하기 때문입니다.

**Independent Test**:
- 8월 12일부터 현재까지의 미생성 구간에 대해 소급 복구 프로세스를 실행합니다.
- 해당 기간 내 모든 대상 종목의 일별 문서, 감성 점수, AI 보고서가 데이터베이스에 채워지는지 확인합니다.

**Acceptance Scenarios**:
1. **Given** 8월 12일 이후 보고서가 미생성된 일자 목록이 있을 때, **When** 소급 복구 프로세스가 실행되면, **Then** 누락된 모든 거래일의 일별 문서 및 최종 AI 보고서가 전수 소급 생성된다.
2. **Given** 파이프라인 실행 중 오류가 발생했을 때, **When** 로그를 확인하면, **Then** 어느 단계에서 어떤 원인으로 중단되었는지 명확한 진단 정보가 기록된다.

---

### Edge Cases (예외 케이스)

- **외부 수급 API 키 부재 또는 외부 통신 장애**: 키움 API Key/Secret이 미설정되어 있거나 통신 장애 발생 시, 치명적 예외를 던지지 않고 스킵 상태로 안전하게 전환하여 후속 모델 추론 및 보고서 생성을 보장해야 함.
- **거래일이 아닌 주말/공휴일**: 수급 데이터나 신규 댓글이 적은 비영업일의 경우 파이프라인이 오류로 중단되지 않고 건너뛰거나(Skip) 정상적으로 처리되어야 함.
- **LLM 서비스 일시 응답 지연 및 특정 종목 실패**: 보고서 생성 시 언어 모델 호출이 지연되거나 실패할 경우, 최대 2회 재시도 후에도 실패하면 해당 종목만 격리/이월하고 나머지 종목의 파이프라인은 정상 완료되어야 함.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 백그라운드에서 정기적인 주기(10분 단위)로 투자자 댓글 수집 및 수급 데이터 갱신 작업을 자동으로 트리거해야 한다.
- **FR-002**: 시스템은 수집된 댓글에 대해 텍스트 전처리, 형태소/토큰 분해, 일별 문서 취합 단계를 순차적이고 무결하게 실행해야 한다.
- **FR-003**: 시스템은 2026년 8월 12일부터 현재까지 누락된 데이터 구간에 대해 10개 KOSPI 전 종목의 감성 지수 분석 및 AI 시장 해설 보고서를 완전하게 전수 소급 생성(Backfill)해야 한다.
- **FR-004**: 시스템은 외부 수급 API 키가 설정되지 않았거나 호출이 불가능할 경우, 파이프라인을 중단시키지 않고 스킵 처리(Graceful Fallback)한 뒤 후속 모델 추론 및 LLM 보고서 생성을 정상 실행해야 한다.
- **FR-005**: 시스템은 파이프라인의 각 단계(수집, 전처리, 토큰화, 일별문서, 수급, 모델추론, 보고서생성)별 시작 시각, 소요 시간, 성공/실패 여부 및 처리 건수를 체계적인 감사 로그로 기록해야 한다.
- **FR-006**: 시스템은 파이프라인 실행 중 프로세스 잠금 충돌이나 비정상 종료 시, 잠금이 영구적으로 남아 향후 스케줄이 무한 대기되는 현상을 방지해야 한다.
- **FR-007**: 시스템은 특정 종목의 LLM 보고서 생성 실패 시 최대 2회 재시도를 수행하고, 실패 시 해당 종목을 격리하여 다른 종목의 파이프라인 진행을 중단시키지 않아야 한다.
- **FR-008**: 웹 사용자 인터페이스는 8월 12일 이후 복구된 모든 날짜에 대해 빈 화면, 대기 중 오류("추론 대기 중"), 기본 문구("저장된 시장 해설이 없습니다") 없이 유효한 보고서와 지표를 표출해야 한다.
- **FR-009**: 시스템은 GPU VRAM 점유를 4GB 이하로 최적화하고 안정적인 서빙 여유 공간을 확보하기 위해 통합 모델 게이트웨이 및 서비스의 기본 LLM 모델을 경량 모델(`qwen3.5-2b`)로 설정해야 한다.

### Key Entities

- **`종목별 일별 댓글 문서 (Daily Stock Document)`**: 특정 거래일과 종목에 수집·집계된 투자자 여론 텍스트 묶음.
- **`감성 지수 및 키워드 분석 결과 (Sentiment Index Result)`**: 일별 문서로부터 산출된 감성 점수, 수급 연관도 및 긍정/부정 기여 키워드 데이터.
- **`AI 시장 해설 보고서 (Market Commentary Report)`**: 감성 지표와 시장 수급 동향을 종합하여 자연어로 생성된 최종 일일 리포트.
- **`파이프라인 실행 기록 (Pipeline Run Record)`**: 자동 수집 및 분석 주기의 단계별 실행 상태, 성공 건수, 실패 원인 등을 추적하는 로그 엔터티.

## Success Criteria *(mandatory)*

- **SC-002**: Pilos 웹 화면에서 8월 12일 이후 임의의 날짜 및 종목 조회 시 "추론 대기 중" 또는 "저장된 시장 해설이 없습니다" 표시 빈도 0건 (100% 정상 보고서 렌더링).
- **SC-003**: 백그라운드 파이프라인이 외부 수급 API 키 부재 환경에서도 오류 없이 10분 정기 주기에 맞추어 감성 추론 및 AI 보고서 생성 전 과정을 자동 완수함.

## Assumptions

- 분석 대상 종목은 사전에 정의된 KOSPI 10개 대표 종목(삼성전자, SK하이닉스, 현대차 등)이다.
- AI 모델 서빙 게이트웨이(vLLM / 언어 모델 서비스)는 기본 경량 모델(`qwen3.5-2b`)을 상주 서빙하여 4GB 이하 VRAM을 유지하며, 보고서 생성 및 챗봇 API 요청을 즉시 처리한다.
- 8월 12일 이후의 댓글 데이터는 외부 데이터 소스로부터 증분 수집 또는 소급 수집이 가능하다.
- 데이터베이스(MySQL)는 정상적으로 쓰기 및 조회가 가능한 상태이다.
- 정기 파이프라인 실행 주기는 기본 10분(600초)으로 설정된다.
- 외부 수급 API 키가 없는 환경에서는 수급 데이터를 스킵하고 댓글 감성 지표 기반으로 보고서 생성을 진행한다.
