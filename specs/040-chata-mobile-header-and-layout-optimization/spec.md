## Clarification & Design Decisions *(speckit-clarify & 2026 Web Trend Review)*

- **Q1 (모바일 카테고리 버튼 배치)**: 모바일 화면(폭 ≤ 768px)에서 6개 카테고리 선택 UI를 어떤 형태로 배치할 것인가?
  - **결정**: **3열 2행(3x2) 컴팩트 그리드** 채택. 6개 카테고리를 행당 3개 버튼씩 2행으로 균등 분할 배치하여 세로 높이를 80~90px로 최소화하고 터치 조작성 확보.
- **Q2 (상단 '분석 설정' 패널 노출 방식)**: 모바일 환경에서 상단 '분석 설정' 패널의 노출 방식을 어떻게 할 것인가?
  - **결정**: **상시 노출 + 여백 컴팩트 최적화 & 적응형 점진적 공개(Progressive Disclosure)** 채택. 대화 시작 전에는 브랜드/카테고리/속성을 컴팩트하게 노출하고, 대화 시작 후에는 본문 여백을 극도로 슬림화하여 대화창 흐름 최우선 보장.
- **Q3 (1클릭 질문 예시 버튼 배치)**: 모바일 화면에서 '💡 질문 예시' 버튼 배치를 어떻게 최적화할 것인가?
  - **결정**: **단일 열 컴팩트 리스트 (패딩 및 폰트 축소, 터치 타깃 44px 규격)** 채택. 질문 텍스트 가독성을 유지하면서 버튼 패딩을 컴팩트화하여 터치 편의성 및 공간 효율 동시 달성.
- **Q4 (모바일 대화 입력창 문구)**: 모바일 화면에서 하단 `st.chat_input`의 플레이스홀더를 어떻게 최적화할 것인가?
  - **결정**: **축약형 모바일 플레이스홀더**(`"브랜드, 제품, 속성을 입력해주세요"`) 적용으로 좁은 화면에서 줄바꿈 및 글자 잘림 방지.
- **Q5 (참조 리뷰 원문 아코디언 모바일 최적화)**: 모바일 환경에서 '📚 참조 리뷰 원문' 아코디언 내부 표시 방식을 어떻게 최적화할 것인가?
  - **결정**: **최대 높이 240px + 모멘텀 내부 스크롤 (컴팩트 카드)** 적용으로 다량의 리뷰가 펼쳐져도 대화창 흐름이 밀리지 않도록 개선.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 모바일 뷰포트 헤더 가림 현상 근본 해결 (Priority: P1) 🎯 MVP

모바일 브라우저(스마트폰 및 폭 768px 이하 반응형 뷰포트)에서 사용자가 최상단으로 스크롤했을 때, 메인 타이틀 "🌿 Oliview" 및 부제목 "올리브영 리뷰 기반 화장품 분석 챗봇"이 Streamlit 기본 헤더 바/툴바에 가려지거나 잘리지 않고 100% 온전하게 노출되어야 한다.

**Why this priority**: 서비스의 첫인상과 브랜드 아이덴티티(로고/타이틀)가 잘리는 현상은 사용자 경험(UX)을 크게 저해하는 최우선 시각적 결함임.

**Independent Test**: 모바일 뷰포트(폭 375px~430px)에서 `https://ezenitac.duckdns.org/bteam/chata/` 접속 시 최상단 타이틀 영역이 0px 잘림 없이 쾌적하게 렌더링되는지 확인.

**Acceptance Scenarios**:
1. **Given** 모바일 브라우저에서 올리챗에 접속하여 최상단으로 스크롤했을 때, **When** 화면을 확인하면, **Then** "🌿 Oliview" 로고 아이콘과 영문 타이틀 상단이 Streamlit 툴바에 가리지 않고 상단 여백(`padding-top: max(3.0rem, env(safe-area-inset-top) + 1.2rem) !important;`)을 유지하며 온전히 표시된다.
2. **Given** Streamlit 기본 상단 바(`header[data-testid="stHeader"]`)가 존재할 때, **When** CSS 스타일이 주입되면, **Then** 상단 헤더 바의 높이 간섭(`height: 0; background: transparent; pointer-events: none;`)이 제거되어 본문 컨텐츠와 겹치지 않는다.

---

### User Story 2 - 모바일 카테고리 선택 3x2 컴팩트 그리드 및 화면 낭비 방지 (Priority: P1)

모바일 화면에서 6개의 카테고리 버튼("스킨케어", "클렌징", "선케어", "립메이크업", "베이스메이크업", "아이메이크업")이 6단 세로 스택으로 길게 늘어서서 화면 전체를 독점하는 현상을 방지하고, 3열 2행(3x2)의 컴팩트한 반응형 그리드로 렌더링되어 한눈에 카테고리를 선택할 수 있어야 한다.

**Why this priority**: 모바일에서 6개 버튼이 세로로 전부 펼쳐지면 사용자가 대화창이나 질문 예시를 보기도 전에 300px 이상의 스크롤 압박을 받게 됨.

**Independent Test**: 모바일 폭(<=768px)에서 카테고리 선택 영역이 2행 3열(행당 3개 버튼)로 컴팩트하게 표시되는지 확인.

**Acceptance Scenarios**:
1. **Given** 화면 폭이 768px 이하인 모바일 환경에서, **When** 카테고리 선택 UI를 렌더링하면, **Then** 6개의 카테고리 버튼이 행당 3개씩(3x2 그리드) 균등 분할(`grid-template-columns: repeat(3, 1fr)`)되어 높이 90px 이내로 컴팩트하게 배치된다.
2. **Given** 특정 카테고리를 탭했을 때, **When** 선택 상태가 활성화되면, **Then** 활성 버튼은 올리브영 테마 컬러(`#2E9E44`)로 강조되고 분석 가능 속성 및 예시 질문이 즉시 갱신되며 터치 딜레이(`touch-action: manipulation`) 없이 반응한다.

---

### User Story 3 - 모바일 분석 설정 및 질문 예시 컴팩트 최적화 (Priority: P2)

모바일 환경에서 브랜드 칩, 속성 안내 카드, 1클릭 예시 질문 목록의 패딩과 글자 크기, 여백을 모바일 화면 비율에 맞게 컴팩트화하여 스크롤 피로도를 최소화하고 대화 영역으로의 빠른 접근을 제공한다.

**Why this priority**: 모바일 사용자는 제한된 화면 크기에서 최소한의 스크롤로 주요 기능을 파악하고 대화를 시작할 수 있어야 함.

**Independent Test**: 모바일에서 초기 로딩 시 분석 설정 영역과 1클릭 예시 질문이 한눈에 파악 가능한 간결한 레이아웃으로 출력되는지 확인.

**Acceptance Scenarios**:
1. **Given** 모바일 환경에서, **When** 지원 브랜드 칩 및 분석 가능 속성 카드가 표시되면, **Then** 불필요한 상하 여백이 축소되고 칩들이 가로 스크롤 또는 유연한 줄바꿈으로 깔끔하게 정렬된다.
2. **Given** 1클릭 예시 질문 버튼 목록이 표시될 때, **When** 모바일 화면에서 보면, **Then** 버튼 패딩이 모바일에 맞게 최적화되어 터치하기 편하면서도 과도한 화면을 차지하지 않는다.

---

### User Story 4 - 데스크톱 레이아웃 무결성 및 모바일 Safe-Area 보장 (Priority: P3)

데스크톱 화면(폭 > 768px)에서는 기존의 2컬럼 [1.6, 1.4] 최적 레이아웃이 100% 그대로 보존되며, 모바일 기기(아이폰 노치/다이나믹 아일랜드 및 홈 인디케이터 바)에서는 `safe-area-inset`이 완벽하게 적용된다.

**Why this priority**: 모바일 스타일 개선으로 인해 데스크톱 UI가 깨지는 부작용을 방지하고 다양한 모바일 단말기 호환성을 보장해야 함.

**Independent Test**: 데스크톱 화면과 모바일 화면을 전환하며 레이아웃이 미디어 쿼리에 따라 완벽히 전환되는지 확인.

**Acceptance Scenarios**:
1. **Given** 데스크톱 브라우저(폭 > 768px)에서 접속했을 때, **When** 레이아웃을 확인하면, **Then** 분석 설정(좌측 1.6)과 질문 예시(우측 1.4)의 2컬럼 그리드가 완벽히 유지된다.
2. **Given** iOS Safari 및 Android 브라우저에서 하단 대화 입력창을 사용할 때, **When** 입력창이 고정되면, **Then** `env(safe-area-inset-bottom)`이 적용되어 홈 인디케이터에 가리지 않는다.

---

## Edge Cases

- **초소형 모바일 화면 (폭 320px ~ 360px)**: 3x2 카테고리 버튼의 텍스트가 줄바꿈되거나 넘치지 않도록 `font-size: 12px~13px` 및 `padding: 6px 2px` 자동 축소 적용.
- **가로 모드 (Landscape 모드)**: 높이가 낮아지는 경우 헤더와 상단 패널이 대화창을 가리지 않도록 상단 여백 자동 조절.
- **스트림릿 재실행 (Rerun)**: 카테고리 변경 시 페이지가 리런되어도 스크롤 위치 및 모바일 그리드 상태가 안정적으로 유지됨.

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 모바일 화면(폭 $\le 768$px)에서 Streamlit의 `.block-container` 상단 패딩을 `max(3.0rem, env(safe-area-inset-top) + 1.2rem) !important;`로 설정하고, `header[data-testid="stHeader"]`의 높이 및 z-index 간섭을 제거(`height: 0; background: transparent; pointer-events: none;`)하여 앱 타이틀("🌿 Oliview")이 상단에서 잘리지 않도록 보장해야 한다.
- **FR-002**: 시스템은 모바일 화면에서 Streamlit의 `st.columns` 컬럼 강제 세로 스택 현상을 CSS `@media (max-width: 768px)` 플렉스/그리드 오버라이드를 통해 제어하여, 카테고리 선택 버튼이 **3열 2행(3x2)**으로 가로 균등 분할(`grid-template-columns: repeat(3, 1fr)`) 렌더링되도록 구현해야 한다.
- **FR-003**: 시스템은 모바일 환경에서 브랜드 칩(`.brand-box`), 분석 속성 카드(`.attribute-card`), 1클릭 질문 예시 버튼의 마진 및 패딩을 축소하여 수직 높이 소모를 기존 대비 40% 이상 절감해야 한다.
- **FR-004**: 시스템은 하단 채팅 입력 래퍼(`[data-testid="stBottom"]`)에 `env(safe-area-inset-bottom)`을 적용하여 최신 스마트폰의 하단 제스처 바와의 겹침을 방지하고, 축약형 플레이스홀더를 제공해야 한다.
- **FR-005**: 시스템은 화면 폭이 768px을 초과하는 데스크톱 환경에서는 기존의 [1.6 : 1.4] 2컬럼 데스크톱 레이아웃과 디자인 토큰을 100% 동일하게 유지해야 한다.

---

## Success Criteria *(mandatory)*

- **SC-001**: 모바일 기기 및 반응형 에뮬레이터(폭 375px~430px)에서 최상단 스크롤 시 앱 헤더("🌿 Oliview")의 상단 잘림이 **0px (100% 온전한 가시성)**이어야 한다.
- **SC-002**: 모바일 카테고리 선택 영역의 수직 높이가 기존 300px+ (6단 세로 스택)에서 **100px 이내 (3x2 컴팩트 그리드)**로 대폭 축소되어 첫 화면에서 대화/예시 영역 접근성이 개선되어야 한다.
- **SC-003**: 데스크톱($>768$px) 환경에서의 2컬럼 레이아웃 회귀(Regression)가 0건이어야 한다.
- **SC-004**: 모든 변경 사항은 `bteam/Oliview_chatbot_a/app.py` CSS 및 레이아웃 구조에 반영되고 실시간 라이브 환경(`https://ezenitac.duckdns.org/bteam/chata/`)에서 즉시 검증되어야 한다.
