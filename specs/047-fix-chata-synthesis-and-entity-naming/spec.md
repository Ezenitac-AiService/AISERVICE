## 1. 문제 분석 및 배경 (Problem Analysis & Context)

올리뷰(Oliview) 챗봇 ChatA 환경에서 열린 추천/카테고리 탐색 질문(예: *"스킨케어에서 수분감 좋은 인기 앰플 추천해줘"*)을 수행했을 때 다음 4가지 핵심 챗봇 로직 결함이 복합적으로 발생하여 사용자 경험을 심각하게 저해하고 있습니다.

```
[사용자 질문] "스킨케어에서 수분감 좋은 인기 앰플 추천해줘"
      │
      ▼
[결함 1. 타겟 상품명 오염]
 ➔ 의도 라우터가 카테고리 발굴 시 질문 문장 전체를 target_name으로 할당
 ➔ 검색 및 컨텍스트 빌더가 실제 리뷰의 진짜 상품명('차앤박 뮤제너 피토 수딩 앰플') 대신 질문 문장을 상품명으로 취급
 ➔ 인용 태그: [스킨케어에서 수분감 좋은 인기 앰플 추천해줘 리뷰 1]
 ➔ 올리브영 링크: query=스킨케어에서 수분감 좋은 인기 앰플 추천해줘 (검색 실패 유발)
      │
      ▼
[결함 2. LLM 합성 타임아웃]
 ➔ 모델 게이트웨이(vLLM) 첫 토큰 생성 지연 시 클라이언트 대기 시간 초과
 ➔ 스트림 생성 중단 및 "[답변 생성 오류: timed out]" 토큰 방출
      │
      ▼
[결함 3. 오염된 L5 캐시 저장 (Poisoned Cache)]
 ➔ L5 응답 캐시가 에러 문자열("[답변 생성 오류: ...]")을 정상 응답으로 오인하여 Redis에 12시간 동안 저장
 ➔ 동일/유사 질문 재인입 시 0.15초 만에 캐시 히트하며 에러 문구를 즉시 반복 재생
      │
      ▼
[결함 4. 리뷰 본문 잔여 대괄호 노출]
 ➔ "차앤박 뮤제너 피토 수딩 앰플 35ml 1+1 기획] 피부 진정과..." 처럼 닫는 대괄호(']')가 전처리되지 않고 본문에 잔류
```

## 2. User Scenarios & Testing *(mandatory)*

### User Story 1 - 카테고리/추천 질의 시 실존 상품명 결속 및 정상 링크 제공 (Priority: P1)

사용자가 특정 단일 제품이 아닌 카테고리/속성 기반의 추천 및 탐색 질의(*"스킨케어에서 수분감 좋은 인기 앰플 추천해줘"*, *"클렌징 오일 피지 세정력 좋은 거 추천해줘"*)를 입력했을 때, 시스템은 질문 전체 문장이 아닌 **실제 데이터베이스에서 발굴된 실존 상품명(예: '차앤박 뮤제너 피토 수딩 앰플')을 정확히 식별**하여 인라인 인용 부호(`[차앤박 뮤제너 앰플 리뷰 1]`)와 올리브영 공식몰 상품 상세 검색 링크(`query=차앤박 뮤제너 피토 수딩 앰플`)를 정상적으로 생성해야 한다.

**Why this priority**: 질문 문장이 상품명으로 둔갑하는 현상은 RAG 신뢰성과 UX를 완전히 파괴하는 치명적인 정합성 결함이므로 최우선 해결되어야 한다.

**Independent Test**:
- *"스킨케어에서 수분감 좋은 인기 앰플 추천해줘"* 질의 시, 하단 아코디언 및 인라인 인용 태그에 질문 문자열이 단 1회도 상품명으로 나타나지 않고 실제 제품명(예: `차앤박...`)으로 표기되는지 검증.
- 올리브영 검색 링크 파라미터가 실제 제품명으로 인코딩되는지 검증.

**Acceptance Scenarios**:
1. **Given** 카테고리/추천 질의가 입력되었을 때, **When** RAG 검색이 데이터베이스에서 리뷰를 수집하면, **Then** 각 리뷰 레코드에 저장된 실제 `product_name` 및 정제 상품명이 인용 태그와 참조 아코디언의 단일 진실 공급원(SSOT)으로 사용되어야 한다.
2. **Given** 발굴된 후보군이 있을 때, **When** 올리브영 공식몰 바로가기 링크를 렌더링하면, **Then** `query={실제_상품명}` 형태로 올바르게 생성되어야 한다.

### User Story 2 - LLM 합성 스트리밍 안정화 및 타임아웃 완화 (Priority: P1)

사용자가 복합적인 분석 및 추천 질문을 요청했을 때, 시스템은 공유 GPU 환경의 큐 대기 시간과 vLLM 초기 추론 지연을 안정적으로 수용하여 `[답변 생성 오류: timed out]` 없이 온전한 마크다운 분석 답변을 실시간 스트리밍으로 수신해야 한다.

**Why this priority**: LLM 스트리밍 실패 시 사용자는 분석 답변을 아예 받지 못하므로 핵심 기능 복구가 필수적이다.

**Independent Test**:
- 실제 vLLM 백엔드가 20초~40초의 초기 지연을 겪는 상황에서도 타임아웃 에러 없이 첫 토큰부터 최종 토큰까지 끊김 없이 수신 완료되는지 검증.

**Acceptance Scenarios**:
1. **Given** 대화 세션에서 LLM 답변 생성을 요청했을 때, **When** 백엔드 모델 응답이 지연되더라도, **Then** 헌법 제6조(시연 모드 지연 허용)에 명시된 완화된 타임아웃 예산 내에서 에러 없이 실시간 토큰을 안정적으로 스트리밍해야 한다.
2. **Given** 불가피한 네트워크 단절 또는 실제 백엔드 다운 시, **When** 에러가 발생하면, **Then** 사용자 친화적인 안내 메시지와 함께 재시도 가이드를 제공해야 한다.

---

### User Story 3 - 에러 응답의 L5 캐시 오염 방지 및 잔여 대괄호 정제 (Priority: P2)

타임아웃이나 예외가 발생한 불완전한 응답은 절대로 Redis L5 응답 캐시에 저장되지 않아야 하며, 실제 구매자 리뷰 원문에 잔존하는 불필요한 대괄호(`]`) 등의 구문 파편이 완벽히 정제되어 깔끔한 문장으로 표시되어야 한다.

**Why this priority**: 에러가 캐시되면 정상 복구된 이후에도 사용자가 계속 에러 응답을 보게 되며, 지저분한 문장 파편은 리뷰 가독성을 떨어뜨린다.

**Independent Test**:
- 타임아웃 발생 테스트 직후 동일 질문을 재요청했을 때 L5 캐시 히트(`⚡ (L5 캐시)`)가 발생하지 않고 새로운 정상 파이프라인이 실행되는지 검증.
- 리뷰 텍스트의 시작 부분에 닫는 대괄호(`]`)가 포함된 데이터가 주어졌을 때 본문 텍스트에서 말끔히 제거되는지 검증.

**Acceptance Scenarios**:
1. **Given** LLM 생성이 실패하거나 에러 토큰(`[답변 생성 오류: ...`)을 포함할 때, **When** 응답 완료 처리를 수행하면, **Then** L5 캐시 저장을 무조건 건너뛰어야(Bypass) 한다.
2. **Given** 원본 리뷰 텍스트가 `"` 또는 `]` 로 시작하거나 카테고리 태그 잔여물이 있을 때, **When** 참조 리뷰 카드로 가공되면, **Then** 깨끗한 한국어 문장만 추출되어야 한다.

## 3. Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 카테고리 발굴/추천 질의(`FEATURE_DISCOVERY`) 시 타겟 엔티티에 임의의 사용자 질문 문자열이 상품명으로 고정되지 않도록, 검색된 실제 리뷰 레코드의 실존 `product_name` 및 `clean_product_name`을 인용 뱃지(`[제품명 리뷰 N]`) 및 참조 카드 제목의 최우선 식별자로 결속해야 한다.
- **FR-002**: 시스템은 올리브영 공식몰 검색 바로가기 URL 생성 시, 질문 문장이 아닌 각 리뷰 레코드의 실제 제품명(`product_name` 또는 `clean_product_name`)만을 검색 파라미터(`query=...`)로 인코딩하여 매핑해야 한다.
- **FR-003**: 시스템은 `AiGatewayClient`의 LLM 스트리밍 클라이언트 타임아웃 구성을 시연 모드(`APP_RUN_MODE=DEMO` / `development`)에 맞게 완화하여, vLLM 모델 지연(최대 180초) 및 초기 스트림 연결 지연(최대 60초) 환경에서 `ReadTimeout` 또는 연결 끊김 없이 온전한 답변을 생성해야 한다.
- **FR-004**: 시스템은 L5 응답 캐시 저장 시, 생성된 텍스트에 에러 키워드(`[답변 생성 오류:`, `timed out`, `Error:`, `Exception:`) 또는 카나리아 이상이 포함된 경우 절대로 Redis L5 캐시에 저장하지 않는 방어 검증(Poison Cache Prevention Gate)을 필수로 수행해야 한다.
- **FR-005**: 시스템은 리뷰 텍스트 전처리 시 `[` 없이 홀로 남은 `]` 또는 양쪽 대괄호 `[...]` 형태의 카테고리/기획명 잔여물을 제거하고, 선행·후행 특수문자를 정제하여 완전한 한국어 리뷰 문장만 클린 텍스트(`clean_text`)로 노출해야 한다.
- **FR-006**: 시스템은 기존 단일 상품 질의(`SINGLE_TARGET`), 다중 제품 비교(`EXPLICIT_COMPARE`), 장단점 분석(`ASPECT_PROS_CONS`), 제로 서치(`ZERO_SEARCH`) 모드와의 하위 호환성을 100% 유지해야 한다.

---

### Key Entities

- **TargetEntity**: 사용자 질의로부터 추출된 타겟 분석 단위. 개별 실존 제품(`product_name`), 브랜드(`brand_name`), 속성(`attribute_query`)을 포함하며, 카테고리 탐색 시 수집된 실존 제품 정보로 동적 갱신된다.
- **ReviewCitation**: BGE-Reranker 및 Document Top-P를 통과한 최종 선별 리뷰 단위. 인라인 인용 태그(`[제품명 리뷰 N]`), 평점(`rating`), 클린 리뷰 텍스트(`clean_text`), 올리브영 검색 URL(`oliveyoung_search_url`)을 갖는다.
- **L5CachePayload**: 최종 검증된 정상 LLM 응답 페이로드. 에러가 전혀 없는 순수 답변 텍스트(`response_text`), 모델 식별자(`model_id`), 문서 해시(`doc_ids_hash`)를 저장한다.

## 4. Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 카테고리/추천 질의(*"스킨케어에서 수분감 좋은 인기 앰플 추천해줘"*) 실행 시, 인라인 인용 태그 및 하단 참조 카드에 사용자 질문 문장이 상품명으로 노출되는 비율 **0% (100% 실존 제품명 결속)**.
- **SC-002**: 올리브영 공식몰 이동 링크 클릭 시, 질문 문장이 검색되지 않고 실제 해당 화장품명이 올리브영 검색창에 입력되는 정확도 **100%**.
- **SC-003**: 시연 환경에서 LLM 스트리밍 답변 생성 실패(타임아웃 에러) 발생률을 **0%로 해소**하고 첫 토큰부터 완료 토큰까지 정상 수신.
- **SC-004**: 에러 응답이 L5 캐시에 저장되어 반복 노출되는 오염 사례 **0건 달성**.
- **SC-005**: 참조 리뷰 텍스트의 선행 괄호 파편(`]`) 노출 결함 **100% 제거**.

## 5. Assumptions

- **인프라 자원**: vLLM 모델 서빙 게이트웨이(`qwen3.5-2b` on port 8081)는 정상 기동 중이며, 공유 GPU/CPU 부하에 따라 첫 토큰 생성까지 최대 30~50초의 대기 시간이 발생할 수 있음을 상정한다 (헌법 제6조 시연 모드 허용).
- **데이터 무결성**: MySQL 및 ChromaDB에 적재된 올리브영 화장품 리뷰 메타데이터는 유효한 `product_name` 및 `brand_name` 필드를 보유하고 있다.
- **캐시 정책**: 기존에 잘못 저장된 오염된 L5 캐시 키는 즉시 무효화(FLUSH or Key Eviction)할 수 있다.
