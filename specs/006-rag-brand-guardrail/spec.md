## User Scenarios & Testing *(mandatory)*

### User Story 1 - 미등록/부재 브랜드 질의 시 엉뚱한 추천 차단 및 정확한 안내 (Priority: P1) 🎯 MVP

사용자가 데이터베이스에 리뷰가 존재하지 않거나 미등록된 브랜드(예: '샤넬', '디올' 등)에 대해 자연어 추천 질의(예: "샤넬 스킨케어 제품 추천해줘")를 입력했을 때, 시스템이 '스킨케어', '제품' 같은 일반 단어로 인해 무관한 타사 제품이나 `[익명]` 브랜드를 엉뚱하게 추천하지 않고, **"죄송합니다. 현재 '샤넬' 브랜드의 등록 상품 및 리뷰 데이터를 찾을 수 없습니다. 올리브영에 등록된 브랜드명으로 다시 검색해 주세요."**라는 명확하고 정확한 안내를 제공해야 합니다.

**Why this priority**: 사용자가 특정 브랜드를 명시했는데 시스템이 무관한 타사 제품이나 `[익명]` 브랜드를 추천하는 것은 AI 서비스의 신뢰도를 치명적으로 훼손하는 심각한 환각(Hallucination)입니다. 부재 브랜드에 대한 정확한 식별과 방어는 최우선 과제입니다.

**Independent Test**:
- 올원챗/올리챗 검색창에 "샤넬 스킨케어 제품 추천해줘" 입력 시, `[익명]`이나 무관한 타사 제품 카드 렌더링 없이 정확한 브랜드 부재 안내 메시지와 빈 카드 상태(0건)가 정상 반환되는지 확인.

**Acceptance Scenarios**:

1. **Given** DB에 리뷰 데이터가 없는 브랜드명이 포함된 자연어 질의, **When** RAG 검색을 실행하면, **Then** 시스템이 해당 브랜드를 감지하고 일반 불용어('스킨케어', '제품')로 인한 무관한 리뷰 검색을 차단하며 표준 미등록 안내문을 반환한다.
2. **Given** DB에 정상 등록된 브랜드명(예: '차앤박', '라네즈', '닥터지')이 포함된 자연어 질의, **When** RAG 검색을 실행하면, **Then** 해당 브랜드와 정확히 일치하는 실제 상품의 리뷰만을 검색하여 상위 추천 카드와 고품질 AI 솔루션을 정상 제공한다.

### User Story 2 - RAG 검색 데이터 품질 정제 및 결측치(`NULL`/빈값/미분류) 원천 차단 (Priority: P1)

사용자가 일반적인 카테고리나 피부 고민(예: "진정 세럼 추천해줘", "지성 피부 수분크림")을 검색했을 때, RAG 검색 엔진이 브랜드명이나 상품명이 누락된 더미 데이터(전체 56.6%에 달하는 결측치 및 '미분류 브랜드/상품')를 검색 대상에서 원천 배제하고, 실제 브랜드명과 상품명이 온전히 검증된 고품질 리뷰 데이터만 추천해야 합니다.

**Why this priority**: 데이터베이스 내 결측치가 RAG 컨텍스트로 전달되면 LLM이 비어있는 대괄호 `[]`를 보고 `[익명]` 브랜드라고 지어내거나, `미분류 브랜드`를 공식 상품인 것처럼 설명하는 2차 환각이 발생합니다.

**Independent Test**:
- 일반 검색 질의("진정 세럼", "보습 크림") 실행 후 반환된 모든 추천 카드의 `brand_name`과 `product_name`이 빈 문자열, `NULL`, `[익명]`, `미분류 브랜드`, `미분류 상품`이 아닌 실제 올리브영 등록 브랜드/상품명인지 100% 검증.

**Acceptance Scenarios**:

1. **Given** RAG 1단계 DB 후보군 조회 쿼리, **When** SQL 조회를 수행하면, **Then** `brand_name`과 `product_name`이 유효하고 실제 존재하는 정제된 데이터만 조회된다.
2. **Given** LLM 컨텍스트 조립 파이프라인, **When** 프롬프트에 주입할 때, **Then** `f"- 상품명: [{res.brand_name}] {res.product_name}"`에 빈 값이나 더미 값이 일체 포함되지 않도록 방어된다.

### User Story 3 - 올리뷰(Oliview) 로그인/회원가입 브랜드 고유번호 조회 404 버그 해결 (Priority: P1)

브랜드 담당자가 올리뷰 웹 포털(`https://ezenitac.duckdns.org/bteam/oliview/`) 로그인 또는 회원가입 모달에서 '브랜드 고유번호 조회'를 실행했을 때, '헤라'를 비롯한 3,062개 브랜드가 404 오류 없이 정상적으로 검색되고 선택될 수 있어야 합니다.

**Why this priority**: 브랜드 조회가 404로 실패하면 사용자가 자신의 브랜드 ID(예: 헤라 ID 68)를 찾을 수 없어 로그인을 진행할 수 없습니다.

**Independent Test**:
- `https://ezenitac.duckdns.org/bteam/oliview/` 접속 후 로그인 페이지에서 [조회하기] 클릭 -> "헤라" 입력 후 [검색] 클릭 -> `헤라 (ID: 68)` 항목이 검색 결과 리스트에 표시되는지 확인.

**Acceptance Scenarios**:

1. **Given** 올리뷰 로그인 페이지의 브랜드 고유번호 조회 모달, **When** "헤라" 또는 특정 브랜드명을 입력하고 [검색]을 누르면, **Then** 404 오류 없이 백엔드 API가 호출되어 일치하는 브랜드 목록이 즉시 렌더링된다.
2. **Given** 검색 결과 리스트의 브랜드 항목, **When** 해당 항목을 클릭하면, **Then** 로그인 폼의 '브랜드 고유 번호' 입력창에 해당 ID가 자동 입력되고 모달이 닫힌다.

### User Story 4 - 불용어(Stopwords) 필터링 및 리랭킹 신뢰도 컷오프 (Priority: P2)

사용자의 자연어 질문에서 의미 없는 일반 명사 및 조사/서술어('제품', '화장품', '추천', '추천해줘', '알려줘', '분석해줘')를 검색 토큰에서 자동으로 제거하고, 코사인 유사도 및 리랭커 점수가 최소 신뢰도 기준치(예: 0.35) 미만인 경우 무관한 제품을 억지로 추천하지 않고 0-결과 폴백을 안정적으로 동작시켜야 합니다.

**Why this priority**: 일반 명사가 검색 토큰에 포함되면 핵심 키워드와 무관한 방대한 리뷰가 SQL OR 조건으로 오염되어 매칭 품질을 떨어뜨립니다.

**Independent Test**:
- 무의미한 외계어 또는 무관한 단어(예: "asdfg 화장품 제품 추천해줘") 질의 시, 낮은 점수의 무관한 제품이 추천되지 않고 "관련 리뷰 데이터를 찾을 수 없습니다" 0-결과 폴백이 정상 트리거되는지 확인.

**Acceptance Scenarios**:

1. **Given** 불용어가 포함된 긴 자연어 문장, **When** 검색 토큰을 추출하면, **Then** 핵심 유의어/속성어만 보존되고 불용어는 토큰 리스트에서 제거된다.
2. **Given** 검색 결과의 리랭커 유사도 점수, **When** 최소 신뢰도 임계값에 미달하면, **Then** 해당 항목은 추천 목록에서 제외되고 유효 결과가 없을 시 0-결과 표준 안내가 반환된다.

## Edge Cases

- **복합 브랜드명 (예: '닥터자르트', 'Dr.G', '라운드랩', 'VT')**: 영문/한글 혼용 브랜드 및 띄어쓰기 차이가 있는 브랜드도 3,062개 브랜드 사전을 통해 유연하게 인식되어야 함.
- **브랜드 없이 속성/카테고리만 질의한 경우 (예: "여드름 진정 패드 추천해줘")**: 특정 브랜드 필터를 강제하지 않고, 결측치 없는 순수 카테고리/속성 기반의 고품질 제품들을 정상 추천해야 함.
- **모달 검색 키워드 미입력 상태로 검색 클릭 시**: 전체 활성 브랜드 목록 또는 상위 50개 브랜드가 깔끔하게 렌더링되어야 함.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `project_ragapi.py` 및 RAG 데이터베이스 조회 시 `brand_name`과 `product_name`이 `NULL`, 빈 문자열(`''`), `미분류 브랜드`, `미분류 상품`인 결측치 데이터를 원천 배제해야 한다.
- **FR-002**: 사용자 자연어 질문에서 3,062개 활성 브랜드 사전을 기반으로 브랜드 엔티티를 자동 추출하여 검색 필터로 적용해야 한다.
- **FR-003**: 사용자가 질문에 특정 브랜드를 명시했으나 DB에 리뷰가 없는 미등록/부재 브랜드일 경우, 타사 제품을 추천하지 않고 즉시 브랜드 부재 표준 안내문을 반환해야 한다.
- **FR-004**: 질의 토큰 추출 시 '제품', '화장품', '스킨케어', '추천', '추천해줘', '분석해줘', '알려줘' 등 일반 불용어(Stopwords)를 제거하여 검색 오염을 방지해야 한다.
- **FR-005**: 리랭킹 결과에 최소 신뢰도 임계값(Relevance Cutoff Threshold)을 적용하여 기준치 미달 항목을 배제하고, 유효 데이터가 없을 시 0-결과 폴백 메시지를 출력해야 한다.
- **FR-006**: RAG 프롬프트 템플릿에 "질문과 일치하지 않는 타사 브랜드를 추천하거나 [익명] 브랜드로 지어내지 말 것"을 명시하는 네거티브 가드레일을 강화해야 한다.
- **FR-007**: `bteam/Oliview_Project/frontend/src/App.jsx`의 `API_BASE_URL`을 `'/bteam/oliview'`로 정규화하여 프론트엔드의 `${baseUrl}/api/...` 호출에서 Double `/api/` 404 오류를 영구 제거해야 한다.
- **FR-008**: 올리챗(ChatA) 및 올원챗(ChatB)에 동일한 결측치 배제 및 브랜드 정확도 가드레일을 동기화 적용해야 한다.

### Key Entities

- **BrandEntityMatcher**: 사용자 자연어 질문에서 3,062개 등록 브랜드를 탐지하고 유효성을 판별하는 모듈
- **StopwordFilter**: 검색 품질을 저해하는 일반 명사 및 서술어 토큰을 제거하는 필터
- **QualityGuardedReview**: 결측치 없이 브랜드명/상품명이 완벽히 검증된 고품질 리뷰 문장 데이터

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 올리뷰 웹 로그인 페이지에서 "헤라" 브랜드 검색 시 `헤라 (ID: 68)` 결과 반환 성공률 **100%** 달성.
- **SC-002**: 부재 브랜드 질의(예: "샤넬 스킨케어 추천") 시 `[익명]` 또는 타사 제품 추천율 **0.0% (완전 차단)** 달성.
- **SC-003**: RAG 추천 카드 및 LLM 답변에서 `[익명]`, `미분류 브랜드`, `미분류 상품` 노출률 **0.0%** 달성.
- **SC-004**: 등록된 브랜드 질의(예: "차앤박 앰플 수분감 분석") 시 정확한 브랜드 일치율 **100%** 달성.
- **SC-005**: E2E 자동화 진단 스크립트(`verify_e2e_services.ps1`) 10개 체크포인트 **100% PASS** 유지.

## Assumptions

- 3,062개 브랜드 목록은 `brands` 테이블에서 실시간 또는 기동 시 캐싱하여 효율적으로 매칭함.
- `review_aspect_sentences`의 59,407건 중 브랜드/상품명이 온전한 25,000여 건의 고품질 데이터만으로도 충분히 풍부한 RAG 추천이 가능함.
