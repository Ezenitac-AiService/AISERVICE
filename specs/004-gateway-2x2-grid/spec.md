  → **A**: **Option A** — 최대 폭 `1000px` 제한 + `768px` 이하 1열 모바일 반응형 전환(가장 균형 잡힌 카드 비율 채택).
- **Q**: 2x2 그리드로 배치될 때 카드 간 텍스트 길이 차이로 인한 높이 불일치를 방지하기 위해 카드의 세로 높이 정렬 방식을 어떻게 적용하시겠습니까?

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 게이트웨이 포털 2x2 균형 그리드 배치 (Priority: P1) 🎯 MVP

사용자가 데스크톱 또는 태블릿 와이드 브라우저로 통합 AI 서비스 포털(`https://ezenitac.duckdns.org/` 또는 `http://localhost:8080/`)에 접속했을 때, 4개의 서비스 카드(A-Team Pilos, B-Team Oliview, 올리챗, 올원챗)가 우측 빈 공간 없이 2행 2열(2x2)로 완벽하게 대칭 정렬되어 안정적이고 균형 잡힌 비주얼을 경험할 수 있어야 합니다.

**Why this priority**: 메인 포털 랜딩 페이지는 사용자가 플랫폼에 진입할 때 가장 먼저 마주하는 첫인상입니다. 3열 구조로 인해 우측에 2개의 빈 슬롯이 남는 비대칭 여백을 제거하고 2x2 직관적 대칭 구도를 완성하여 UX 만족도를 극대화합니다.

**Independent Test**:
- 데스크톱 브라우저(1024px 이상)에서 메인 페이지(`/`) 로드 시 4개의 카드가 상단 2개, 하단 2개로 2x2 그리드 배열되는지 시각적 및 DOM 구조로 검증.

**Acceptance Scenarios**:

1. **Given** 데스크톱 화면 해상도(>= 768px), **When** 메인 게이트웨이 포털(`/`)에 접속하면, **Then** 4개의 서비스 카드가 2열(2 Columns) 대칭 레이아웃으로 렌더링되어 우측 빈 열 없이 꽉 찬 구도를 유지한다.
2. **Given** 2x2 그리드 내부 카드들, **When** 텍스트 길이가 서로 상이하더라도, **Then** 각 행(Row)의 카드 높이가 자동으로 동일하게 맞춰지고 하단 링크 버튼이 일직선으로 수평 정렬된다.
3. **Given** 모바일 및 좁은 뷰포트(< 768px), **When** 화면 폭을 축소하면, **Then** 2열 그리드가 자동으로 1열(1 Column) 반응형 세로 스택으로 전환되어 가독성을 유지한다.
4. **Given** 그리드 컨테이너 내부 구조, **When** 마크업을 점검하면, **Then** 불필요한 공백/줄바꿈 태그(`<br>`) 없이 시맨틱 Flex/Grid 카드 요소들만 깔끔하게 정렬된다.

---

## Edge Cases

- **초고해상도 와이드 모니터(1440px ~ 4K)**: 컨테이너의 `max-width`가 `1000px`로 제한되어 카드가 과도하게 가로로 늘어지지 않고 우아한 카드 비율을 유지함.
- **중간 해상도 태블릿(768px ~ 1024px)**: 2열 구조를 안정적으로 유지하면서 카드 내부 텍스트 줄바꿈이 깨지지 않음.

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 메인 포털의 그리드 컨테이너는 데스크톱 뷰포트에서 정확히 2열(`grid-template-columns: repeat(2, 1fr)`)로 동작해야 한다.
- **FR-002**: 메인 포털 카드의 최대 폭(`max-width`)은 2열 배열에 최적화된 `1000px`로 설정되어 중앙 정렬되어야 한다.
- **FR-003**: 768px 이하 모바일 뷰포트 미디어 쿼리에서는 1열(`grid-template-columns: 1fr`)로 유연하게 반응해야 한다.
- **FR-004**: 컨테이너 내부의 불필요한 줄바꿈 요소(`<br>`)를 제거하고 깨끗한 시맨틱 구조를 유지해야 한다.
- **FR-005**: 4개 서비스 카드는 각 행별로 높이가 자동 균등화(`height: 100%`)되며, 호버 애니메이션(상승, 글로우 효과) 및 링크 기능이 기존과 동일하게 완벽 작동해야 한다.

### Key Entities

- **ServiceCard (UI Component)**: 게이트웨이 메인에 표시되는 4개 서브서비스 진입 링크 카드 (Pilos, Oliview, 올리챗, 올원챗)
- **GridContainer (Layout Element)**: 4개의 서비스 카드를 감싸는 2x2 반응형 CSS Grid 컨테이너

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 1024px 이상 화면에서 4개 서비스 카드가 정확히 2x2(2행 2열) 대칭 그리드로 100% 렌더링된다.
- **SC-002**: 우측 비어있는 3번째 열 공간이 완전히 제거된다 (불필요한 공백 0%).
- **SC-003**: 768px 이하 모바일 화면 전환 시 1열 반응형 레이아웃이 100% 정상 작동한다.
- **SC-004**: 메인 포털 로딩 속도 및 기존 서비스 링크 동작(Pilos, Oliview, ChatA, ChatB)에 일체의 기능 저하나 회귀 결함이 없다.

---

## Assumptions

- 4개의 서비스 카드가 플랫폼의 핵심 서브서비스 구성으로 고정 유지된다.
- 게이트웨이 컨테이너의 Nginx 정적 파일(`/usr/share/nginx/html/index.html`)을 업데이트하여 즉시 반영된다.
