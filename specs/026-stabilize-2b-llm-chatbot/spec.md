## Clarifications

### Session 2026-08-20

- **Q**: VRAM에 상주시킬 모델 구성은 어떻게 되는가? (임베딩, 리랭킹, Qwen 2B, 프롬프트 가드?)  
  → **A**: **VRAM 상주 모델은 총 3개**(`bge-m3` 임베딩, `bge-reranker-v2-m3` 리랭커, `qwen3.5-2b` 생성 LLM)입니다. 프롬프트 인젝션 가드 및 얼리 인텐트 게이트는 별도 신경망 모델이 아닌 **순수 Python/CPU 기반 고속 정규식·서명·카나리 토큰(Canary Token) 룰 엔진(VRAM 0MB)**으로 동작합니다.
- **Q**: 챗봇 및 분석 작업별 토큰 예산은 일반 RAG에 2K, 심층 분석 리포트 등에 4K를 적용하는 하이브리드 정책으로 확정하는가?  
  → **A**: **3단계 하이브리드 토큰 예산 정책 확정**:
    1. **일반 대화형 RAG 검색**: `max_tokens = 2048` (2K) → 1,000~1,500자 완성형 뷰티 가이드 솔루션 생성 (지연시간 3~5초, 절단 0%).
    2. **심층 분석 및 전수 비교 리포트 / Pilos 코멘터리**: `max_tokens = 4096` (4K) → 다중 제품 장단점 및 심층 통계 분석 장문 리포트 생성.
    3. **빠른 의도분류 및 메타데이터 필터링**: `max_tokens = 512` → 초고속 라우팅 및 전처리 (지연시간 0.5초 이내).
    * `model_gateway`의 `qwen3.5-2b`는 `n_ctx = 16384` (16K)로 가동되어 입력 컨텍스트(최대 12K)와 4K 출력 토큰을 안정적으로 수용합니다.
- **Q**: 기존 다중 모델 라우팅 코드를 삭제하지 않고, 환경 설정 플래그로 `단일 모델 모드`와 `다중 모델 모드`를 전환할 수 있도록 구현하는 것에 대한 타당성은?  
  → **A**: **기술적·아키텍처적으로 100% 타당하며 강력히 권장됩니다.**
    1. **`SINGLE_MODEL_MODE=true` (기본값, 현재 8GB VRAM 환경)**: 클라이언트 요청 모델명에 상관없이 현재 상주 중인 `qwen3.5-2b`로 자동 라우팅하여 불필요한 프로세스 킬/스와핑 핑퐁을 원천 차단하고 무중단 서빙 보장.
    2. **`SINGLE_MODEL_MODE=false` (향후 16GB/24GB+ GPU 마이그레이션 환경)**: 기존의 다중 티어(4B/9B) 동적 핫스왑 및 다중 모델 서빙 코드를 100% 보존하여, 설정 플래그 전환만으로 즉시 복원 가능.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 2B 단일 모델 기반 챗봇 RAG 맞춤 솔루션 무중단 완결 생성 (Priority: P1)

사용자가 Oliview 챗봇 A (`/bteam/chata`) 또는 챗봇 B (`/bteam/chatb`)에 화장품/스킨케어 분석 및 추천 질문을 입력했을 때, 시스템은 8GB GPU 환경에서 메모리 부족(OOM)이나 모델 스와핑 지연 없이 `qwen3.5-2b` 모델을 통해 문장 절단 없이 완결된 고품질 맞춤 뷰티 가이드 답변을 10초 이내에 스트리밍으로 제공받는다.

**Why this priority**: 챗봇의 핵심 가치는 사용자의 질문에 대해 끊김 없이 완결된 답변을 신속하게 제공하는 것이며, 타임아웃과 문장 절단은 사용자 경험을 완전히 파괴하는 치명적 결함이기 때문.

**Independent Test**: 챗봇 A 및 B에 복합 다면 질문(예: "여름철 기름기 잡고 모공 커버 잘되는 매트 쿠션 추천해줘")을 전송하여, 타임아웃 오류나 토큰 중간 잘림 없이 온전한 서론-본론-추천제품-결론이 담긴 뷰티 솔루션이 생성되는지 확인.

**Acceptance Scenarios**:

1. **Given** `SINGLE_MODEL_MODE=true` 상태에서 `model_gateway`에 `qwen3.5-2b`가 상주 서빙 중일 때, **When** 사용자가 챗봇 B에서 추천 질문을 전송하면, **Then** 10초 이내에 실시간 스트리밍이 시작되고 중간에 끊기지 않고 완전한 맞춤 솔루션 본문이 생성 완료된다.
2. **Given** 챗봇 A에서 5건의 참조 리뷰를 선별했을 때, **When** 최종 종합 답변 생성을 요청하면, **Then** `[답변 생성 오류: timed out]` 없이 8초 이내에 완결된 종합 분석 답변이 화면에 출력된다.

### User Story 2 - Pilos 데이터 파이프라인과 챗봇 동시 실행 시 안정성 보장 (Priority: P2)

Pilos 배치/증분 수집 및 일별 LLM 보고서 생성(`generate_llm_reports`) 작업이 백그라운드에서 대량 실행되는 중에도, 챗봇 사용자의 질의가 모델 스와핑 핑퐁이나 서버 프로세스 강제 재시작 없이 높은 우선순위로 즉시 처리된다.

**Why this priority**: 서비스 환경에서는 백그라운드 데이터 수집/분석 파이프라인과 실시간 대화형 챗봇이 동일한 LLM 게이트웨이를 공유하므로, 배치 작업이 실시간 챗봇 서비스를 중단시키지 않아야 함.

**Independent Test**: Pilos 일별 보고서 배치 작업을 구동한 상태에서 챗봇 A/B에 동시에 질의를 보내어, 모델 게이트웨이가 프로세스 재시작(Kill/Reload) 없이 즉시 응답을 반환하는지 검증.

**Acceptance Scenarios**:

1. **Given** Pilos 워커가 수백 건의 일별 문서를 처리 중일 때, **When** 챗봇 사용자가 대화창에 질문을 입력하면, **Then** `model_gateway`는 모델 변경 없이 동일한 `qwen3.5-2b` 런타임에서 우선순위 스케줄러를 통해 챗봇 요청을 먼저 처리한다.
2. **Given** Pilos와 챗봇이 동시에 요청을 보낼 때, **When** 게이트웨이 로그를 관측하면, **Then** `OOM Auto-restart recovery`나 `503 Service Unavailable`이 발생하지 않는다.

### User Story 3 - 설정 플래그 기반의 무손실 아키텍처 및 미래 고용량 GPU 마이그레이션 보장 (Priority: P3)

향후 RTX 4090(24GB) 또는 클라우드 고용량 VRAM 환경으로 인프라를 확장할 때, 코드 재작성 없이 `.env`의 `SINGLE_MODEL_MODE=false` 플래그 설정만으로 4B/9B 다중 모델 라우팅 체제로 즉시 전환할 수 있다.

**Why this priority**: 단기적인 하드웨어 제약 해결을 위해 기존 멀티티어 코드를 파괴하지 않고, 설정 기반 모드 분리를 통해 장기적 소프트웨어 자산을 완벽히 보존하기 위함.

**Independent Test**: `SINGLE_MODEL_MODE=false` 플래그를 테스트 환경에 주입했을 때, 모델 게이트웨이가 기존의 다중 모델 카탈로그 및 동적 핫스왑 경로를 정상적으로 인식하고 동작하는지 검증.

**Acceptance Scenarios**:

1. **Given** `SINGLE_MODEL_MODE=false`로 설정되었을 때, **When** 클라이언트가 `qwen3.5-4b`를 요청하면, **Then** 시스템은 기존 다중 모델 핫스왑 관리자를 통해 모델 로드를 시도한다.
2. **Given** `SINGLE_MODEL_MODE=true`로 설정되었을 때, **When** 클라이언트가 `qwen3.5-4b`를 요청하더라도, **Then** 시스템은 프로세스 재시작 없이 상주 중인 `qwen3.5-2b`로 안전하게 폴백 서빙한다.

---

### Edge Cases

- **초대형 리뷰 텍스트 유입**: 검색된 리뷰 문장이 과도하게 많을 경우, 16K 컨텍스트 윈도우 내에서 안전하게 수용되도록 토큰 예산 초과 방지 필터링이 정상 작동해야 한다.
- **스트리밍 도중 네트워크 일시 순단**: 클라이언트 연결이 끊어지더라도 서버 자원 누수 없이 즉시 스트림이 정리되어야 한다.
- **보안 가드레일 오탐(False-Positive)**: 화장품 브랜드명이나 성분 설명(예: '식물나라', '브링그린 티트리')이 포함된 정상 응답을 시스템 프롬프트 유출로 오인하여 차단하지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (설정 기반 서빙 모드 분리 및 2B 단일 모드 표준화)**: `model_gateway`에 `SINGLE_MODEL_MODE` 환경변수를 도입하고, 기본값 `true`에서는 모든 LLM 요청을 상주 `qwen3.5-2b`로 고정 라우팅하여 8GB VRAM 환경에서 스와핑 핑퐁 및 OOM을 원천 차단한다.
- **FR-002 (VRAM 점유 및 3개 모델 상주 보장)**: GPU VRAM에는 오직 3개 모델(`bge-m3` 임베딩, `bge-reranker-v2-m3` 리랭커, `qwen3.5-2b` LLM)만 100% 상주시키며, 총 VRAM 점유량이 5.5GB 이하를 유지하도록 보장한다. (프롬프트 가드는 CPU 0MB VRAM 유지)
- **FR-003 (컨텍스트 윈도우 및 하이브리드 토큰 예산 최적화)**: `qwen3.5-2b` 서빙 컨텍스트 윈도우를 16,384(16K)로 설정하고, 의도분류(512) / 일반 RAG(2048) / 심층 리포트(4096)의 3단계 하이브리드 `max_tokens` 체계를 적용하여 문장 중간 절단을 원천 방지한다.
- **FR-004 (스트리밍 및 파싱 안정성)**: 챗봇 B의 SSE 스트리밍 수신부에서 청크 파싱 중단, 버퍼 유실, 조기 스트림 닫힘 없이 끝까지 온전히 브라우저로 렌더링되도록 보장한다.
- **FR-005 (타임아웃 임계값 및 회복력 강화)**: 챗봇 A 및 B의 HTTP 클라이언트 타임아웃을 최소 60초 이상으로 보장하고, 일시적 부하 발생 시 자동 재시도 및 상태 복구 메커니즘을 지원한다.
- **FR-006 (보안 가드레일 정밀도 개선)**: 챗봇 A/B의 출력 안전성 검증 룰에서 화장품 상품명/리뷰 데이터에 대한 오탐(False-Positive)을 방지하도록 패턴 매칭을 정교화한다.
- **FR-007 (설정 동기화 및 하위 호환성 보존)**: Root, B-Team, Model Gateway의 `.env` 및 `config.json` 설정 파일들을 `qwen3.5-2b` 단일화 및 하이브리드 토큰 규격으로 동기화하되, 기존 다중 모델 카탈로그 및 어댑터 코드는 100% 보존한다.

### Key Entities

- **Model Gateway (vllm-serv-gateway)**: `SINGLE_MODEL_MODE` 플래그를 지원하며, `qwen3.5-2b` (포트 8089/8081, n_ctx=16K), `bge-m3` (포트 8090), `bge-reranker-v2-m3` (포트 8091) 3개 모델을 통합 서빙하는 고속 추론 게이트웨이.
- **Prompt Injection & Intent Guardrail**: CPU 및 정규식/카나리 토큰 기반으로 동작하는 초경량 보안 게이트웨이 엔진 (VRAM 0MB).
- **Oliview Chatbot A (`oliview_chatbot_a`)**: 의도 분류(512) 및 리뷰 다면 RAG 분석(2048)을 수행하는 8501 포트 Streamlit 기반 대화 서비스.
- **Oliview Chatbot B (`oliview_chatbot_b`)**: 하이브리드 벡터 검색, 리랭킹 및 심층 RAG 합성(2048/4096)을 수행하는 8002 포트 FastAPI 백엔드 + 프론트엔드 엔진.
- **Pilos Pipeline (`pilos-web` / `pilos-worker`)**: 일별 주식/감정 신호 집계 및 LLM 시장 코멘터리(1400/4096)를 생성하는 5000 포트 분석 파이프라인.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 챗봇 A 및 챗봇 B의 질문 응답 성공률 100% 달성 (타임아웃 오류율 0%, 토큰 중단 절단율 0%).
- **SC-002**: 챗봇 질의 시 첫 번째 토큰 출력 시간(TTFT) 1.5초 이내, 1,500자 완성형 답변(2K) 생성 시간 5초 이내, 4K 심층 리포트 생성 시간 15초 이내 달성.
- **SC-003**: Pilos 대량 배치와 챗봇 동시 구동 시 Model Gateway 프로세스 재시작(OOM Crash) 0회 유지.
- **SC-004**: 전체 GPU VRAM 사용량을 6.0GB 이내로 안정적으로 억제하여 Pascal/GTX 1070 환경에서 100% 무결점 상주 서빙 달성.
- **SC-005**: `SINGLE_MODEL_MODE=false` 토글 시 기존 다중 모델 핫스왑 경로가 무손실로 동작하는 하위 호환성 100% 보존.

## Assumptions

- **하드웨어 환경**: 호스트는 NVIDIA GeForce GTX 1070 (8GB VRAM) 단일 GPU를 사용하며, WSL2 Docker 기반으로 모든 컨테이너가 구동된다.
- **마이그레이션 확장성**: 향후 16GB/24GB+ GPU 플랫폼 도입 시 `SINGLE_MODEL_MODE=false` 변경만으로 4B/9B 다중 모델 라우팅을 즉각 활성화할 수 있다.
- **모델 성능 타당성**: `qwen3.5-2b`는 FP16/Q4_K_M 양자화 상태에서 한국어 대화 및 RAG 요약 성능이 우수하며, 16K 컨텍스트와 하이브리드 토큰 예산(2K/4K)이 주어질 경우 4B 모델과 동등 이상의 실전 품질을 발휘한다.
