## User Scenarios & Testing *(mandatory)*

### User Story 1 - 메인 컨텐츠 영역과 일관된 대화 입력창 너비 정렬 (Priority: P1)

사용자가 다양한 화면 크기(와이드 모니터, 노트북, 데스크톱)에서 Oliview 챗봇 A 페이지에 접속했을 때, 화면 하단의 대화 입력창이 상단 분석 설정 패널 및 대화 메시지 영역과 동일한 최대 너비(1200px 기준)와 중앙 정렬 레이아웃을 유지하여 시각적 통일감과 일체감을 경험할 수 있어야 한다.

**Why this priority**: 현재 하단 입력창이 상단 본문 컨텐츠 영역과 무관하게 전체 화면 너비로 넓게 퍼져 있어 사용자 시선 이동이 부자연스럽고 UI 완성도가 저하되므로, 즉각적인 시각적 조화와 직관적인 사용성을 제공하는 최우선 과제이다.

**Independent Test**: 브라우저 창 크기를 가로 1920px(FHD), QHD, 4K 등 와이드 해상도로 조절하여 페이지를 확인했을 때, 하단 입력창의 좌우 시작/끝 지점이 상단 헤더 및 대화 메시지 목록의 좌우 경계선과 오차 없이 일치하는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 1200px 이상의 넓은 디스플레이(1920x1080 등)에서 챗봇 페이지를 열었을 때, **When** 사용자가 화면을 확인하면, **Then** 하단 대화 입력창의 가로 폭이 메인 컨텐츠 박스(최대 1200px)와 동일하게 중앙에 정렬되어 표시된다.
2. **Given** 대화 메시지가 누적되어 스크롤이 발생하는 상태에서, **When** 사용자가 하단 입력창에 포커스를 주거나 텍스트를 입력할 때, **Then** 입력창 영역의 너비나 중앙 정렬 위치가 흔들리지 않고 안정적으로 유지된다.

---

### User Story 2 - 반응형 화면 크기 변경 시 자동 너비 동기화 (Priority: P2)

사용자가 모바일 기기, 태블릿, 분할 화면(Split Screen), 창 크기 리사이징을 수행할 때, 하단 대화 입력창이 상단 본문 컨텐츠의 너비 변화에 맞춰 좌우 여백과 너비를 유연하게 동기화하여 표시되어야 한다.

**Why this priority**: 다양한 디바이스 환경 및 멀티 윈도우 작업 환경에서도 입력창이 화면 밖으로 넘치거나 본문과 어긋나지 않도록 완벽한 반응형 사용자 경험을 보장하기 위함이다.

**Independent Test**: 브라우저 폭을 1200px 이하(1024px, 768px, 480px, 360px 등)로 점진적으로 줄이거나 늘렸을 때, 하단 입력창이 본문 컨텐츠 영역과 동일한 패딩과 비율로 축소/확대되는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 브라우저 가로 폭이 1200px 미만인 태블릿 또는 모바일 뷰포트에서, **When** 페이지를 로드하거나 화면 크기를 조절하면, **Then** 하단 입력창이 화면 가로 폭에 비례하여 부드럽게 줄어들며 본문 좌우 여백과 균일한 간격을 유지한다.
2. **Given** 브라우저 창 크기를 실시간으로 드래그하여 조절할 때, **When** 화면 폭이 변경되면, **Then** 하단 입력창과 본문 컨텐츠가 지연 없이 동일한 너비로 동기화되어 레이아웃 깨짐이 발생하지 않는다.

---

### Edge Cases

- 초고해상도(4K/Ultrawide 21:9 이상) 모니터 환경에서 하단 입력창이 화면 양 끝으로 과도하게 벌어지거나 좌우로 치우치지 않고 중앙 메인 컨테이너 너비 내에 정확히 고정되어야 함.
- 1클릭 예시 질문 버튼 클릭 또는 긴 질문 입력 시 입력창 내부 텍스트 줄바꿈이 발생해도 입력창 전체 컨테이너의 가로 폭과 중앙 정렬이 왜곡되지 않아야 함.
- 대화 히스토리 내의 아코디언(참조 리뷰 원문 펼침) 토글 시에도 하단 고정 입력창의 레이아웃 위치 및 너비가 영향을 받지 않아야 함.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 하단 고정 대화 입력창 컨테이너의 최대 가로 너비(Max-Width)를 메인 본문 컨테이너와 동일한 1200px로 제한하여 일체감을 제공해야 한다.
- **FR-002**: 시스템은 하단 대화 입력창 영역을 뷰포트 중앙에 자동으로 수평 정렬(Margin Auto)하여 상단 대화 메시지 및 설정 패널과 수직 축을 정확히 일치시켜야 한다.
- **FR-003**: 시스템은 뷰포트 너비가 1200px 미만인 디바이스 환경에서 하단 입력창의 좌우 패딩 및 가로 폭이 본문 컨텐츠와 동일한 비율로 유연하게 반응(Responsive)하도록 처리해야 한다.
- **FR-004**: 시스템은 브라우저 스크롤, 대화 메시지 추가, 참조 리뷰 확장 등의 동적 UI 인터랙션 중에도 하단 입력창의 너비와 위치가 어긋나지 않고 화면 하단에 안정적으로 고정되도록 해야 한다.
- **FR-005**: 시스템은 기존 챗봇의 모든 기능(1클릭 예시 버튼 연동, 엔터키 입력, 텍스트 전송, 세션 히스토리 복원)에 어떠한 기능적 장애나 회귀 결함도 유발하지 않아야 한다.
- **FR-006**: 시스템은 하단 고정 대화 입력창 바에 미세한 반투명 블러(Backdrop-Filter / Semi-transparent background) 처리를 적용하여 대화 스크롤 메시지와의 겹침을 방지하고 본문(1200px)과 자연스럽게 융합되도록 해야 한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 1200px 이상의 모든 데스크톱 화면에서 하단 입력창의 좌우 시작점이 상단 메인 컨텐츠 영역의 좌우 경계선과 100% 일치(정렬 오차 0px)해야 한다.
- **SC-002**: 모바일(360px~480px), 태블릿(768px~1024px), 데스크톱(1200px~2560px) 전 구간에서 입력창 잘림이나 화면 가로 스크롤(오버플로우)이 0건이어야 한다.
- **SC-003**: 창 크기 변경 및 대화 입력 시 시각적 떨림이나 레이아웃 밀림(Layout Shift) 현상 없이 매끄러운 반응형 렌더링을 유지해야 한다.

## Assumptions

- 대상 챗봇 애플리케이션은 `https://ezenitac.duckdns.org/bteam/chata/`에 서빙되는 Oliview Chatbot A (`bteam/Oliview_chatbot_a/app.py`)이다.
- 메인 컨텐츠의 기준 최대 너비는 기존 스타일 가이드에 정의된 `1200px`을 표준으로 유지한다.
- 사용자는 모바일 기기부터 울트라와이드 모니터까지 다양한 브라우저 환경에서 동일한 브랜드 아이덴티티와 정돈된 UI 레이아웃을 기대한다.
