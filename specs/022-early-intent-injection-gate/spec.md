## Clarifications

### Session 2026-08-19
- Q: 비도메인(코딩, 일반상식, 게임 제작 등) 및 우회 인젝션 질의를 DB 검색 및 리랭킹 전에 초고속으로 판별하여 챗봇 A와 챗봇 B에서 조기 차단(Early Exit)하기 위해 어떤 의도 판별 방식을 채택할까요? → A: **A-B 하이브리드 방식**: Tier 1A(초고속 <1ms 규칙/패턴 엔진으로 명백한 코딩/게임/탈옥 즉시 차단) + Tier 1B(Llama Prompt Guard 2 86M 로컬 경량 모델)를 결합하여 챗봇 A/B에 공통 적용.
- Q: Llama Prompt Guard 2 (86M) 모델을 시스템에 어떤 방식으로 탑재하여 구동할까요? → A: **Option B (순수 로컬 서빙 Standalone Local Only)**: 외부 API 종속성 없이 로컬 환경(`transformers` 기반 로컬 경량 추론, 메모리 약 300MB, 추론 레이턴시 ~15ms)에서 `Llama-Prompt-Guard-2-86M` 또는 동급 경량 분류기를 직접 구동.
- Q: 2026년 8월 최신 업계 보안 표준 및 운영 정책을 어떻게 스펙에 통합할까요? → A: **OWASP LLM Top 10 (2025/2026 v2.0) 및 NIST AI RMF 기반 6대 운영 보안 거버넌스 정책**을 스펙 요구사항에 전면 반영.
- Q: 6차에 걸친 다중 페르소나 심층 분석에서 도출된 24대 핵심 견고성(Hardening) 대책을 어떻게 반영할까요? → A:
  1. **위장형 인젝션 방어**: "식물나라 토너 분석 파이썬 코드로 짜줘" 등 뷰티 키워드가 혼입되어도 코드 작성/게임 제작 등의 행위 동사가 결합되면 엄격 차단.
  2. **은유적 표현 오탐 방지**: "코딩하느라 주름 생겼는데 아이크림 추천", "피부 뒤집어져 게임 오버될 것 같은데 진정 크림 추천" 등 일상 은유 표현은 문맥 가드로 오탐 없이 정상 통과.
  3. **신조어/부정형 뷰티 질문 지원**: "절대 쓰면 안 되는 토너", "극혐인데 산뜻한 수분크림", "썬크림/선크림" 등 100종 뷰티 온톨로지 매칭.
  4. **샌드위치 인젝션 방어**: 최대 입력 300자 제한 및 긴 질의 슬라이딩 윈도우 스캔.
  5. **SRE 안정성 & 오프라인 Graceful Fallback**: 86M 모델 싱글톤 캐싱, 웜업 및 모델 부재/예외 시 Tier 1A 규칙 엔진 단독 자립 모드 보장.
  6. **비동기 블로킹 방지**: FastAPI 비동기 컨텍스트에서 `run_in_threadpool` 스레드 풀 격리.
  7. **로그 폭주 방어**: 동일 패턴 차단 이벤트 디바운싱 및 구조화 로깅.
  8. **버퍼 완전 교체**: 출력 가드레일 감지 시 오염 문자열 겹침 없이 표준 거절 문구로 완전 대체.
  9. **PII 마스킹 감사 로깅**: 로그 출력 시 주민번호, 전화번호, 이메일, 계좌번호 등 개인정보 자동 마스킹.
  10. **클라이언트 XSS 살균**: 프론트엔드 마크다운/HTML 엔티티 강제 살균 및 스크립트 실행 차단.
  11. **세션 히스토리 오염 방지**: 차단된 공격 질의는 Redis 대화 히스토리에 적재하지 않고 다음 턴 LLM 프롬프트 주입 원천 차단.
  12. **원시 제어문자 및 NULL 바이트 살균**: 입력 최상단에서 `\x00` 및 C0/C1 비가시 제어 문자 100% 제거.
  13. **다국어 글로벌 뷰티 질의 지원**: 영문/일문/중문 핵심 뷰티 어휘(`sunscreen`, `toner`, `serum`, `化粧水`, `防晒霜` 등) 화이트리스트 등록으로 정상 통과.
  14. **저장형 리뷰 인제스천 사전 살균**: RAG DB 적재 시점 태그/시스템 지시어 살균.
  15. **봇넷 사전 정찰 프로빙 방어**: 연속 차단 세션에 대한 지연 응답(Tarpit) 페널티 부여.
  16. **보안 검증 캐싱**: 정상 검증 질의의 Redis 보안 캐싱(0ms / 0W 바이패스) 지원.
  17. **한글 자모 분리 난독화 복원**: 분리된 초성/중성/종성 자모 완성형 복원 및 NFC 정규화.
  18. **Zero-Connection DB Gate**: DB 커넥션 풀 획득 이전에 완전 차단 (커넥션 점유 0회).
  19. **유해 의약품 및 불법 제조 안전 가드**: 스테로이드/불법 민간요법 시 전문의 상담 가이드라인 반환.
  20. **보안 텔레메트리 메트릭 계측**: `oliview_guardrail_blocked_total` 및 레이턴시 메트릭 계측 지원.
  21. **멀티스레드 동시성 안전 보장**: `torch.inference_mode()` 및 스레드 락 적용으로 레이스 컨디션 원천 차단.
  22. **ONNX INT8 양자화 어댑터 지원**: 80MB 메모리, 3~5ms 초저지연 가속 엔진 구조 지원.
  23. **타사 브랜드 비방 방지 중립 가드**: 비방 유도 질문에 대한 객관적 팩트 기반 중립 응답 원칙 준수.
  24. **무중단 동적 피처 플래그**: `ENABLE_EARLY_GUARDRAIL` 런타임 제어 지원.

## Problem Statement & Root Cause Analysis

### 1. 현행 시스템 결함 분석 (Root Causes)
1. **사전 검사 범위의 한계 (Narrow Signature Focus)**:
   - 기존 가드레일은 "이전 지시 무시", "DAN 모드" 등 협소한 키워드만 검사하여, `"파이썬으로 스네이크 게임 만들어줘"`, `"양자역학 공식 알려줘"`, `"주식 매수 추천해줘"`와 같은 **비도메인(Out-of-Domain) / 역할 탈취 우회 질의**를 사전에 걸러내지 못함.
2. **파이프라인 리소스 낭비 (Heavy Downstream Execution on Invalid Queries)**:
   - 비도메인/인젝션 질의임에도 불구하고 벡터 임베딩, DB 하이브리드 검색, GPU BGE 리랭킹(16.7초 소요)을 모두 실행한 뒤 최종 4B LLM 추론까지 거치는 막대한 서버/GPU 자원 낭비 발생.
3. **참조 리뷰 데이터 오염 및 UI 노출 결함 (Irrelevant Context Exposure)**:
   - 무관한 질의임에도 검색된 임의의 화장품 리뷰 5건이 프롬프트 컨텍스트에 주입되고, UI 하단에 "참조 리뷰 원문" 아코디언으로 사용자에게 불필요하게 노출됨.
4. **스트리밍 누출 마스킹 깨짐 결함 (Corrupted String Concatenation)**:
   - 4B 모델이 시스템 프롬프트 내부 태그(`<reference_reviews>`)를 출력할 때, 마스킹 로직이 기존 토큰 버퍼에 이어붙여지면서 문장이 흉측하게 겹쳐 출력되는 버그 발생.

## 4-Layer Defense-in-Depth Architecture

```text
┌───────────────────────────────────────────────────────────────────────────┐
│                     🛡️ 2026 다층 방어 체계 (Defense-in-Depth)              │
├───────────────────────────────────────────────────────────────────────────┤
│ [Layer 1: 선제적 초저지연 게이트 (<20ms)]                                  │
│   ├── Step 1A: ReDoS 안전 정규식 + 비도메인/코딩 블랙리스트 (<1ms)         │
│   └── Step 1B: 초경량 전용 보안 모델 (Llama Prompt Guard 2 86M, ~15ms)    │
├───────────────────────────────────────────────────────────────────────────┤
│ [Layer 2: RAG 데이터 구획 격리 (Structural Sandboxing)]                    │
│   ├── XML 태그 격리: <reference_reviews>, <user_query> 구획화             │
│   ├── 하단 지시문 재강화 (Instruction Defense): 신뢰할 수 없는 데이터 선언  │
│   └── 동적 카나리아 토큰 (Canary Token): UUID 기반 시스템 지침 오염 탐지   │
├───────────────────────────────────────────────────────────────────────────┤
│ [Layer 3: 사후 출력 가드레일 (Output Guardrail)]                           │
│   ├── 시스템 프롬프트/카나리아 토큰 누출 실시간 차단                       │
│   └── 버퍼 완전 교체(Buffer Replacement): 오염 텍스트 겹침 방지          │
└───────────────────────────────────────────────────────────────────────────┘
```

## 6대 AI 챗봇 운영 보안 거버넌스 정책 (Operational Security Policies)

1. **정책 1: 입력 및 도메인 제어 정책 (Input & Domain Scoping Policy)**
   - 화장품/뷰티 상담과 무관한 질의(코딩, 수학, 번역, 일반상식, 게임제작 등)는 **DB 검색 및 LLM 생성을 일체 거치지 않고 20ms 내 즉시 조기 종료(Early Exit)**.
   - 유니코드 NFKC 정규화 및 제로 너비 공백 문자 제거 의무화.
2. **정책 2: 기밀 정보 및 데이터 유출 방지 정책 (Data Loss Prevention - DLP)**
   - 시스템 프롬프트, 역할 지시문, 내부 DB 스키마, SQL 쿼리, API 키 등 내부 인프라 정보 유출 요청 100% 차단.
3. **정책 3: 안전 거절 응답 단일화 정책 (Safe Refusal Standard)**
   - 보안/도메인 차단 시 내부 기술 정보를 노출하지 않고 친절한 단일 표준 뷰티 안내 메시지만 반환:
     > *"올리뷰는 올리브영 화장품 리뷰 분석 전용 AI입니다. 시스템 지침 변경이나 관련 없는 요청에는 답변할 수 없습니다. 궁금하신 화장품에 대해 질문해 주세요! 🌿"*
   - 차단 시 검색 결과 목록은 빈 배열(`[]`)로 강제하여 참조 리뷰 아코디언 노출 0건 보장.
4. **정책 4: 보안 감사 로깅 및 관측 가능성 (Audit Logging & Observability)**
   - 모든 차단 이벤트는 `[SECURITY_ALERT]` 접두사와 함께 JSON 구조화 로그(`timestamp`, `event_id`, `matched_rule`, `risk_level`, `action_taken`)로 기록.
5. **정책 5: DoS 자원 고갈 방어 (Resource & Rate Limiting Guard)**
   - 차단된 질의의 DB 쿼리 수 0회, 리랭킹 호출 0회, 4B LLM 토큰 생성 0회 보장.
6. **정책 6: 지속적 레드팀 및 회귀 검증 (Continuous Red Teaming & Regression)**
   - 최신 인젝션/탈옥/비도메인 테스트셋 30종에 대한 100% 차단율 및 정상 뷰티 질의 50종에 대한 오탐률 0% 유지.

## User Scenarios & Acceptance Criteria *(mandatory)*

### User Story 1 - 비도메인 및 우회 인젝션 질의 20ms 내 Zero-Cost 조기 차단 (Priority: P1) 🎯 MVP

사용자가 화장품과 무관한 코딩("파이썬으로 스네이크 게임 만들어줘"), 수학, 번역, 일반상식, 역할 탈취 질의를 입력했을 때, 시스템이 DB 검색, 리랭킹, 4B 모델 호출 없이 20ms 이내에 즉시 조기 차단하여 표준 안내를 출력하고 자원 낭비를 방지한다.

**Acceptance Scenarios**:
1. **Given** 사용자가 "파이썬으로 스네이크 게임 만들어줘"를 입력할 때, **When** 시스템이 수신하면, **Then** DB 검색, 임베딩, BGE 리랭킹, 4B 모델을 전혀 호출하지 않고 (20ms 이내), 표준 뷰티 가이드 메시지를 즉시 반환한다.
2. **Given** 비도메인/인젝션으로 조기 차단된 경우, **When** 화면이 렌더링되면, **Then** 하단 "참조 리뷰 원문" 아코디언이 일체 노출되지 않는다 (`reference_reviews = []`).

---

### User Story 2 - Llama Prompt Guard 2 86M 로컬 추론 기반 탈옥 방어 (Priority: P1)

정교한 다국어 우회 탈옥(DAN, 프롬프트 누출, 가상 페르소나 공격) 시도 시, 로컬에 적재된 경량 86M 보안 모델이 15ms 이내에 `INJECTION` 또는 `JAILBREAK`로 탐지하여 안전하게 차단한다.

**Acceptance Scenarios**:
1. **Given** 고도화된 다국어 탈옥 프롬프트가 입력될 때, **When** Llama Prompt Guard 2 86M 모델이 분류하면, **Then** `INJECTION`/`JAILBREAK` 확률이 임계값을 초과하여 즉시 안전 거절 응답을 반환한다.

---

### User Story 3 - 정상 뷰티 상담 질의의 무결성 통과 (Priority: P2)

올리브영 화장품, 브랜드, 성분, 피부 고민, 리뷰 분석에 관한 모든 정상 질문은 지연 없이 통과되어 고품질 RAG 검색 및 4B 모델 분석을 정상 수행한다.

**Acceptance Scenarios**:
1. **Given** 사용자가 "차앤박 앰플 수분감 어때?" 또는 "지성 피부에 맞는 순한 토너 추천"을 입력할 때, **When** 선제적 게이트를 통과하면, **Then** 오탐(False Positive) 없이 정상 RAG 파이프라인을 거쳐 제품 추천 및 리뷰 분석을 정상 출력한다.

---

### User Story 4 - 스트리밍 마스킹 무결성 및 버퍼 완전 교체 (Priority: P3)

만약 4B 모델 생성 중 카나리아 토큰이나 시스템 태그가 누출되더라도, 이전 스트림 버퍼와 거절 문구가 섞여 출력되지 않고 즉시 깨끗한 단일 표준 거절 문구로 완전 대체된다.

**Acceptance Scenarios**:
1. **Given** 4B 모델이 시스템 태그나 카나리아를 출력할 때, **When** 출력 가드레일이 트리거되면, **Then** 기존 버퍼를 초기화하고 단일 표준 거절 문구만 온전하게 출력한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 질의 수신 즉시(Step 0) 보안 인젝션 및 비도메인(코딩, 수학, 번역, 일반상식, 게임제작 등)을 단일 통합 게이트에서 판별하는 `evaluate_query_safety_and_intent()` 엔진을 구현해야 한다.
- **FR-002**: `Tier 1A` 규칙 필터는 ReDoS-safe 정규식 및 비도메인 시그니처 사전을 사용하여 **1ms 이내**에 명백한 공격 및 비도메인 질의를 선제 차단해야 한다.
- **FR-003**: `Tier 1B` 로컬 보안 분류기는 `Llama-Prompt-Guard-2-86M` 또는 동급 경량 분류기를 로컬 CPU/GPU(메모리 ~300MB)에 적재하여 **15ms 이내**에 정밀 공격을 3진 분류해야 한다.
- **FR-004**: 도메인/보안 부적합 질의로 판정된 경우, 시스템은 **DB 검색, 벡터 임베딩, BGE 리랭킹, 4B LLM 추론을 일체 호출하지 않고 즉시 조기 종료(Early Exit)**해야 한다.
- **FR-005**: 조기 종료 시 전체 파이프라인 레이턴시는 **20ms 이하**를 달성해야 한다 (기존 16.7초 대비 800배 이상 단축).
- **FR-006**: 조기 종료 시 반환 메타데이터는 `selected_review_count=0`, `reference_reviews=[]`, `model_used="guardrail-early-blocked"`로 설정되어 UI에서 무관한 참조 리뷰 아코디언이 노출되지 않아야 한다.
- **FR-007**: 정상 화장품/뷰티/피부 질의에 대해서는 오탐률(False Positive Rate) **0%**를 보장해야 한다.
- **FR-008**: 4B 모델 출력 가드레일 트리거 시, 기존 누적 버퍼의 내용을 완전히 무시하고 오직 표준 안전 거절 문구(`SAFE_BLOCKED_RESPONSE`)만 단독 반환해야 한다.
- **FR-009**: 모든 차단 이벤트는 `[SECURITY_ALERT]` 접두사와 함께 구조화된 JSON 로그로 기록해야 한다.
- **FR-010**: 본 선제적 게이트는 Chatbot A(`bteam/oliview_core/pipeline.py`)와 Chatbot B(`bteam/Oliview_chatbot_b/project_ragapi.py`)에 동일 공통 모듈로 통합 적용되어야 한다.
