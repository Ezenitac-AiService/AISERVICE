## 1. 개요 및 배경 (Overview & Background)

### 1.1 배경
현재 B팀의 올리브영 화장품 리뷰 분석 챗봇인 **올리챗(OllyChat)**은 질문 입력 시 단순 정적 스피너(`st.spinner("검색 모델과 LLM을 불러오고 답변을 생성하고 있습니다...")`) 또는 단순 로딩 표시기만 노출되어 있습니다.
사용자는 내부적으로 질의 분석, 키워드/벡터 하이브리드 검색, BGE-Reranker 순위 재정렬, 2B/4B 계층형 LLM 추론 중 어느 단계가 수행 중인지, 서버가 멈춘 것인지 정상 동작 중인지 파악하기 어렵습니다.

### 1.2 목적
최신 생성형 AI 서비스(Perplexity, ChatGPT Search 등)의 사용자 경험 표준에 맞춰, 올리챗 질의 처리의 **전체 RAG 파이프라인(질문 분석 ➡️ 하이브리드 검색 ➡️ 리랭킹 ➡️ LLM 심층 생성) 진행 단계를 실시간 시각적 인디케이터(Step Progress / Status Cards)**로 사용자에게 생생하게 전달하고, 답변 완료 시 **검색 근거/참조 리뷰 수/소요 시간 메타데이터**를 제공하여 신뢰성과 만족도를 극대화합니다.

## 2. 사용자 시나리오 및 인수 기준 (User Scenarios & Acceptance Criteria)

### 2.1 User Story 1 (Priority: P1) - 실시간 4단계 파이프라인 진행 시각화
> **As a** 올리챗을 사용하는 화장품 소비자  
> **I want to** 질문을 입력했을 때 분석이 어떤 단계로 진행되고 있는지 화면에서 실시간으로 확인하고 싶다  
> **So that** 시스템이 멈추지 않고 내 질문을 깊이 있게 분석하고 있음을 인지하고 신뢰할 수 있다.

- **Acceptance Scenario 1.1 (단계별 순차 전환)**:
  - **Given** 사용자가 "컬러그램 탕후루 탱글 꿀로스의 발림성 장단점을 분석해줘"를 질문창에 입력하고 전송한다.
  - **When** 백엔드에서 RAG 프로세스가 시작되면,
  - **Then** 화면에 실시간 상태 컨테이너가 열리며 다음 단계가 순차적으로 활성화 및 완료(아이콘 변화)된다:
    1. 🔍 **질문 의도 및 화장품 속성 분석 중** (브랜드/상품명/속성 키워드 파싱)
    2. 📚 **리뷰 하이브리드 검색 중** (BM25 키워드 + BGE-M3 밀집 벡터 임베딩)
    3. ⚖️ **BGE-Reranker 순위 재정렬 중** (상위 고관련 리뷰 선별 및 스코어링)
    4. 🧠 **LLM 심층 분석 및 맞춤 답변 생성 중** (Qwen3.5 리뷰 종합 생성)
  - **And** 답변 작성이 완료되면 컨테이너가 `✅ 리뷰 종합 분석 완료` 상태로 전환된다.

### 2.2 User Story 2 (Priority: P2) - 검색 근거 및 처리 메타데이터 열람 (Transparency & Evidence)
> **As a** 제품 성분 및 실제 리뷰 근거를 꼼꼼히 확인하고 싶은 사용자  
> **I want to** 답변 하단 또는 진행 상태 카드에서 실제로 참조된 리뷰 수와 분석 소요 시간을 확인하고 싶다  
> **So that** AI의 답변이 허구가 아닌 실제 올리브영 구매자 리뷰에 기반했음을 검증할 수 있다.

- **Acceptance Scenario 2.1 (메타데이터 뱃지 및 아코디언)**:
  - **Given** 올리챗 답변이 성공적으로 출력된 상태에서,
  - **When** 사용자가 답변 상단/하단의 완료 카드(또는 접이식 아코디언)를 확인하면,
  - **Then** `총 소요 시간(예: 1.8초)`, `분석 대상 리뷰 수(예: 검색 15건 ➡️ 최종 선별 5건)`, `적용 모델(2B/4B)` 정보가 깔끔한 뱃지/요약문으로 표시된다.

### 2.3 User Story 3 (Priority: P2) - 예외 및 폴백 상황 시 친절한 상태 안내
> **As a** 네트워크 지연이나 모델 스왑 상황에 마주친 사용자  
> **I want to** 지연이나 모델 전환이 발생할 때 화면에 명확한 안내를 받고 싶다  
> **So that** 에러로 오해하여 새로고침하거나 이탈하지 않고 기다릴 수 있다.

- **Acceptance Scenario 3.1 (2B Fallback 및 지연 안내)**:
  - **Given** 4B 모델 로드 대기 시간이 길어지거나 Fallback이 발생할 때,
  - **When** 4단계(답변 생성)가 진행되면,
  - **Then** 상태 박스에 `초고속 2B 모델로 즉시 전환하여 신속히 답변을 작성 중입니다...`와 같은 친절한 실시간 가이드 텍스트가 표시된다.
- **Acceptance Scenario 3.2 (검색 0건 및 장애 복구 인터랙션)**:
  - **Given** 입력 키워드 매칭 실패로 검색 결과가 0건이거나 백엔드 에러가 발생했을 때,
  - **When** 상태 박스가 `⚠️ 경고` 또는 `❌ 오류` 상태로 전환되면,
  - **Then** 상태 박스 하단에 원클릭 `다시 시도(Retry)` 버튼과 함께 질문 범위를 완화할 수 있는 `추천 검색어 칩(Chip)`이 노출되어 사용자가 즉시 재탐색할 수 있다.

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 파이프라인 단계별 상태 이벤트 정의
- **FR-001**: 챗봇 백엔드(`05.chatbot.py`, `project_ragapi.py`)는 질의 처리 수명 주기를 다음 4가지 핵심 단계(Phase)로 분할하고 실시간 콜백(Callback/Generator)을 제공해야 한다:
  - Phase 1: `INTENT_ANALYSIS` (질문 메타데이터 및 카테고리/속성 추출)
  - Phase 2: `HYBRID_SEARCH` (ChromaDB BGE-M3 벡터 임베딩 + BM25 키워드 검색)
  - Phase 3: `RERANKING` (BGE-Reranker-v2 교차 순위 재정렬)
  - Phase 4: `LLM_SYNTHESIS` (계층형 모델 기반 최종 답변 생성)
  - Phase 5: `COMPLETED` (최종 완료 및 메타데이터 산출)

### 3.2 올리챗 A (Streamlit: `06.app.py`) 시각적 인터페이스 요구사항
- **FR-002**: 기존의 단순 `st.spinner()`를 대체하여, Streamlit의 `st.status()` 또는 동적 카드 컴포넌트를 적용해야 한다.
- **FR-003**: 각 단계가 진행될 때마다 상태 메시지와 아이콘이 동적으로 업데이트(예: ⏳ 진행 중 ➡️ 🟢 완료)되어야 한다.
- **FR-004**: 최종 완료 후 `st.status(state="complete", expanded=False)`로 전환되어 본문 가독성을 위해 자동 축약(Collapsed)되고, 사용자가 클릭 시 언제든 세부 4단계 진행 내역을 다시 펼쳐볼 수 있어야 한다.
- **FR-005**: 분석 완료 카드 내부에 `검색된 리뷰 요약` 또는 `참조 키워드`가 간결하게 노출되어야 한다.

### 3.3 올리챗 B (FastAPI / Web UI: `index.html`) 시각적 인터페이스 요구사항
- **FR-006**: 웹 클라이언트 화면에서 질문 전송 시 메시지 상단에 세련된 Step Indicator(타임라인 스텝 바 또는 애니메이션 펄스 뱃지)가 표시되어야 한다.
- **FR-007**: SSE(Server-Sent Events) 또는 단계별 콜백 스트림을 통해 실시간으로 단계 변경 이벤트(`{ "step": "search", "label": "리뷰 검색 중..." }`)를 수신하고 UI를 즉시 갱신해야 한다.

### 3.4 성능 및 UX 제약
- **FR-008**: 진행 상태 표시 UI 렌더링으로 인한 부가 지연 시간(Overhead)은 총 50ms 미만이어야 한다.
- **FR-009**: 모바일 화면(반응형 웹)에서도 진행 상태 박스가 넘치거나 깨지지 않고 간결하게 축약 표시되어야 한다.
- **FR-010**: 검색 결과가 0건이거나 에러 발생 시 상태 박스가 즉각 `⚠️ 경고` 또는 `❌ 오류` 상태로 명확한 원인 메시지와 함께 종료되어야 하며, 상태 박스 하단에 원클릭 '다시 시도(Retry)' 버튼 및 추천 완화 검색어 칩(Chip)을 제공하여 빠른 복구를 지원해야 한다.
- **FR-011**: 4단계(LLM 답변 생성) 진입 시, 생성 토큰을 버퍼링 없이 즉시 화면에 전달하는 실시간 타이핑 스트리밍(`st.write_stream` / SSE)을 적용하여 첫 토큰 응답 시간(TTFT) 체감을 극대화해야 한다.
- **FR-012**: 답변 하단에 `📖 실제 참조 리뷰 원문 (N건)` 접이식 아코디언 컴포넌트를 렌더링하여, 사용자가 클릭 시 RAG 및 리랭킹으로 선별된 상위 리뷰(평점, 피부타입/속성, 리뷰 원문 본문)를 깔끔하게 열람할 수 있어야 한다.
- **FR-013**: 이전 대화 기록(Chat History) 복원 또는 재렌더링 시, 과거 메시지의 진행 과정 상태 컨테이너는 기본적으로 `✅ 리뷰 종합 분석 완료` 축약 요약 뱃지 형태로 렌더링되며 사용자가 클릭 시에만 세부 4단계 내역이 펼쳐져야 한다.

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **NFR-001 (호환성 및 비파괴성)**: 기존 05.chatbot.py의 검색 정확도, 리랭킹 알고리즘 및 2B/4B 라우팅 로직의 무결성을 100% 보존해야 한다.
- **NFR-002 (일관된 디자인)**: 올리브영 테마 컬러(`--olive-green: #2f9e44`, 부드러운 그린 톤, 프리미엄 다크/라이트 카드)와 조화롭게 어우러지는 모던 디자인을 적용한다.
- **NFR-003 (접근성)**: 스크린 리더 및 시각적 구분을 위해 텍스트 라벨과 아이콘을 항상 함께 제공한다.

## 5. 성공 지표 (Success Criteria)

- **SC-001**: 올리챗 A 및 B에서 질문 전송 후 0.2초 이내에 1단계 진행 상태가 화면에 시각적으로 표시된다.
- **SC-002**: 4단계(분석 ➡️ 검색 ➡️ 리랭킹 ➡️ 생성) 전환이 빠짐없이 순차적으로 시각 업데이트된다.
- **SC-003**: 답변 생성 완료 시 사용자가 참조 리뷰 수와 소요 시간을 1클릭 이내(또는 자동 노출)로 확인할 수 있다.
- **SC-004**: 진행 상태 시각화 도입 후에도 총 응답 생성 지연 시간이 5% 이상 증가하지 않는다.
