## User Scenarios & Testing *(mandatory)*

### User Story 1 - 깨짐 없는 종목 로고 및 안정적인 주식 감정지수 탐색 (Priority: P1)

사용자가 주식 감정지수 서비스에 접속하여 상위 10대 인기 종목(SK하이닉스, 삼성전자, 에코프로비엠 등)을 조회할 때, 모든 종목의 로고 이미지가 결함 없이 즉시 표시되고, 네트워크 일시 오류나 미등록 이미지의 경우에도 종목 이니셜 컬러 아바타로 우아하게 대체되어 대시보드가 빠르고 안정적으로 렌더링되어야 한다.

**Why this priority**:
실제 접속 로그 분석 결과, 전체 404 오류(2,608건)의 42% 이상이 종목 로고 이미지 누락으로 인해 발생하고 있습니다. 이는 사용자 경험을 저해하고 서버 로그를 오염시키므로 최우선 해결 대상입니다.

**Independent Test**:
주식 감정 서비스 메인 및 종목별 상세 화면에 진입했을 때, 10대 종목의 로고 이미지가 404 오류 없이 100% 정상 표시되며, 이미지 누락 시 이니셜 아바타가 정상 렌더링되는지 검증합니다.

**Acceptance Scenarios**:
1. **Given** 사용자가 주식 감정 대시보드에 접속했을 때, **When** 상위 종목 목록 및 상세 리포트를 열람하면, **Then** 모든 종목의 로고 이미지가 누락(깨진 이미지) 없이 선명하게 표시된다.
2. **Given** 네트워크 환경에서 로고 이미지를 요청할 때, **When** 해당 이미지 리소스를 호출하면, **Then** 404 리소스 없음 오류가 발생하지 않고 유효한 이미지 응답을 수신한다.
3. **Given** 이미지 경로가 유효하지 않거나 로딩에 실패한 경우, **When** 화면이 렌더링되면, **Then** 깨진 이미지 대신 해당 종목명의 첫 글자가 들어간 고유 색상의 원형 아바타가 표시된다.

### User Story 2 - 모바일 및 메신저 링크 유입 사용자 경험 최적화 (Priority: P2)

스마트폰 사용자(특히 카카오톡 등 모바일 메신저 대화방 링크를 클릭하여 유입된 사용자)가 서비스를 방문했을 때, 화면 잘림이나 여백 왜곡 없이 최적화된 반응형 레이아웃을 경험하고, 메신저 공유 시 서비스별(포털, Pilos, Oliview, 올리챗) 특화된 맞춤형 미리보기 카드(제목, 설명, 썸네일)를 확인할 수 있어야 한다.

**Why this priority**:
접속자 분석 결과, 전체 접속의 27%가 모바일이며, 특히 카카오톡 인앱 브라우저를 통한 유입이 전체 브라우저 중 2위(19.3%, 2,481건)를 기록하고 있어 모바일 환경 최적화가 필수적입니다.

**Independent Test**:
모바일 기기 및 인앱 브라우저 환경에서 메인 포털과 서브 서비스를 열람했을 때, 상하단 잘림 없이 부드럽게 스크롤 및 터치가 작동하고, 각 서브 링크 공유 시 해당 서비스의 맞춤형 미리보기 카드가 생성되는지 확인합니다.

**Acceptance Scenarios**:
1. **Given** 사용자가 메신저나 SNS에 특정 서브 서비스(예: Pilos, Oliview, 올리챗) 링크를 공유했을 때, **When** 대화방에 링크가 렌더링되면, **Then** 해당 서브 서비스 고유의 명칭, 핵심 설명, 대표 썸네일 이미지가 포함된 미리보기 카드가 올바르게 나타난다.
2. **Given** 모바일 인앱 브라우저로 서비스에 진입했을 때, **When** 페이지를 탐색하거나 챗봇 대화를 진행하면, **Then** 스마트폰 노치 영역이나 하단 소프트키 영역에 가려짐 없이 모든 UI 요소를 온전히 조작할 수 있다.

### User Story 3 - 통합 포털 실시간 큐레이션 및 서비스 유입 전환 강화 (Priority: P3)

사용자가 서비스 첫 진입점인 통합 포털 랜딩 페이지에 방문했을 때, 현재 가장 주목받는 주식 감정 테마 및 화장품 뷰티 핫 키워드 요약 정보를 비동기 Fetch로 지연 없이 첫 화면에서 즉시 확인하고, 관심 있는 서비스로 원클릭 이동할 수 있어야 한다.

**Why this priority**:
현재 통합 포털 방문 비중(2.4%)이 낮고 서브 서비스로의 유입 전환 연결고리가 약합니다. 포털에 실시간 요약 큐레이션을 제공하여 사용자 체류 시간을 늘리고 서비스 간 시너지를 창출합니다.

**Independent Test**:
통합 포털 메인 페이지에 진입했을 때 실시간 인기 하이라이트 위젯이 비동기로 부드럽게 로드되고, 위젯 클릭 시 해당 서브 서비스의 상세 화면으로 매끄럽게 연결되는지 테스트합니다.

**Acceptance Scenarios**:
1. **Given** 사용자가 통합 포털 메인에 접속했을 때, **When** 랜딩 화면이 로드되면, **Then** 백엔드 API를 비동기 호출하여 최신 주식 감정지수 상위 종목 요약과 화장품 리뷰 인기 카테고리 큐레이션이 한눈에 표시된다.
2. **Given** 포털의 큐레이션 위젯을 확인할 때, **When** 특정 종목이나 뷰티 키워드를 클릭하면, **Then** 해당 서브 서비스(Pilos 또는 Oliview/올리챗)의 대응 페이지로 즉시 이동한다.

### User Story 4 - 백엔드 API 예외 회복력 및 안정적 서빙 보장 (Priority: P4)

사용자가 뷰티 리뷰 분석 대시보드나 챗봇 서비스를 이용할 때, 특정 브랜드 데이터가 비어있거나 초기화 중인 예외 상황에서도 시스템 오류(500 에러) 화면 대신 친절한 안내 메시지나 기본 상태가 제공되어 중단 없는 서비스 이용이 가능해야 한다.

**Why this priority**:
분석 결과 일부 브랜드 상품/카테고리 API에서 간헐적인 500 오류(44건)가 관측되었습니다. 시스템 예외 상황에 대한 안전망을 갖추어 사용자 경험을 보호합니다.

**Independent Test**:
데이터가 존재하지 않거나 비정상적인 브랜드 ID를 요청했을 때, 500 서버 크래시 대신 빈 목록과 안내 메시지가 정상적으로 반환되는지 확인합니다.

**Acceptance Scenarios**:
1. **Given** 특정 브랜드의 상품이나 카테고리 정보가 초기 상태일 때, **When** 사용자가 해당 브랜드 대시보드를 조회하면, **Then** 서버 에러 화면이 발생하지 않고 준비 중 안내 또는 빈 목록이 정상 렌더링된다.

---

### Edge Cases

- **초저속 네트워크 환경**: 이미지 로딩이 지연되거나 비동기 Fetch 호출 중일 때 스켈레톤/플레이스홀더 UI가 유지되어 레이아웃 깜빡임(CLS)을 방지하는지 여부
- **다양한 모바일 화면 비율**: 초소형 화면(320px)부터 폴더블/태블릿 기기까지 반응형 레이아웃이 무너지지 않는지 여부
- **비정상/악의적 쿼리 파라미터 유입**: 잘못된 형식의 엔드포인트 요청 시 서버 크래시 없이 표준 오류 응답(400)으로 안전하게 방어되는지 여부

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 10대 주요 종목의 로고 이미지 리소스를 누락 없이 유효한 경로로 서빙해야 하며, 로드 실패 시 동적 CSS/SVG 컬러 이니셜 아바타로 즉각 대체해야 한다.
- **FR-002**: 시스템은 서비스 링크가 메신저(카카오톡 등) 및 소셜 플랫폼에 공유될 때 통합 포털, Pilos, Oliview, 올리챗 각 서비스별 맞춤형 대표 썸네일, 타이틀, 요약 설명(Open Graph)을 완전하게 제공해야 한다.
- **FR-003**: 시스템은 모바일 및 인앱 브라우저 화면의 뷰포트와 안전 영역(Safe Area)을 준수하여 UI 요소가 화면 밖으로 잘리지 않도록 반응형으로 표시해야 한다.
- **FR-004**: 통합 포털 메인 페이지는 각 서브 서비스(Pilos, Oliview)의 기존 REST API를 비동기 Fetch로 호출하여 실시간 하이라이트 요약 큐레이션을 지연 없이 렌더링해야 한다.
- **FR-005**: 포털의 하이라이트 요약 위젯은 클릭 시 해당 서브 도메인 서비스의 상세 경로로 직관적인 네비게이션을 지원해야 한다.
- **FR-006**: 백엔드 API는 데이터 미존재 또는 일시적 조회 실패 상황에서도 시스템 장애(500 에러)를 유발하지 않고 안전한 기본값과 상태 코드를 반환해야 한다.
- **FR-007**: 시스템은 정적 자원(CSS, JS, 폰트, 이미지)에 대해 적절한 캐싱 정책을 적용하여 반복 접속 시 불필요한 네트워크 대역폭 낭비를 방지하고 로딩 속도를 최적화해야 한다.

---

### Key Entities

- **서비스 메타데이터 (Service Metadata)**: 서비스별(포털/Pilos/Oliview/챗봇) 고유 명칭, 요약 설명, 대표 썸네일 이미지 URL, 공유용 오픈그래프 속성
- **종목 정적 애셋 (Stock Static Asset)**: 종목 코드, 종목명, 공식 로고 이미지 파일 및 서빙 경로, 대체 이니셜 아바타 속성
- **실시간 포털 큐레이션 (Portal Curation)**: 비동기 조회된 주식 감정지수 하이라이트(상위 종목명, 감정 상태), 뷰티 리뷰 하이라이트(인기 브랜드, 주요 키워드), 서비스 바로가기 링크

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 주식 종목 로고 이미지와 관련된 404 리소스 누락 오류 발생 건수를 **0건(100% 제거)**으로 감축한다.
- **SC-002**: 카카오톡 등 주요 메신저 링크 공유 시 각 서브 서비스별 맞춤형 미리보기 카드(이미지, 타이틀, 설명)가 100%의 확률로 정상 노출된다.
- **SC-003**: 모바일 기기(너비 360px ~ 430px) 및 인앱 브라우저 환경에서 주요 화면의 UI 요소 잘림 및 가로 스크롤 결함이 발생하지 않는다.
- **SC-004**: 브랜드 API 비정상 요청 및 초기 데이터 조회 시 500 서버 오류 발생률을 **0%**로 유지한다.
- **SC-005**: 정적 자원 캐시 재사용률(HTTP 304 또는 메모리 캐시)을 개선하여 반복 방문자의 초기 페이지 렌더링 지연시간을 단축한다.

## Assumptions

- **기존 데이터베이스 보존**: 현재 구축된 5만여 건의 리뷰 데이터 및 주식 수급/감정 분석 데이터베이스의 무결성은 그대로 유지된다.
- **단일 게이트웨이 도메인 유지**: `https://ezenitac.duckdns.org` 공인 도메인 및 사설 네트워크 격리 아키텍처를 기반으로 최적화가 수행된다.
- **브라우저 호환성 표준**: 최신 모바일 브라우저(Chrome, Safari, Samsung Internet, KakaoTalk Webview)의 웹 표준 규격을 기준으로 최적화한다.
