# AGENTS.md

## 1. 목적

이 문서는 Codex 등 AI 에이전트의 행동만 규정합니다. 사람 팀원의 파일 배치·데이터·Git 규칙을 이 문서에 복사하지 않습니다.

팀장은 작업 지시자이자 최종 통합 책임자입니다.

## 2. 영역별 정본

| 판단 대상 | 확인할 정본 |
|---|---|
| 목표·필수 구현 범위·우선순위·담당자 | Notion 기획안 |
| 폴더·파일 배치·의존 방향 | `docs/ARCHITECTURE.md` |
| 데이터 의미·라벨·상태·필드 | `docs/DATA_CONTRACT.md` |
| Git 작업 방식 | `docs/GIT_WORKFLOW.md` |
| 효력이 생긴 기술 결정 | `docs/DECISIONS.md` |

각 문서는 자신의 영역에서만 권위가 있습니다. 정본끼리 충돌하면 임의의 우선순위를 적용하지 않고 팀장에게 보고합니다. 현재 작업에 대한 팀장의 명시적 지시가 가장 우선합니다.

## 3. 작업 전

- 관련 정본을 먼저 확인합니다.
- 생성·수정·삭제 예정 파일과 영향 범위를 보고합니다.
- `논의 중`, `합의됨·반영 중`, `적용 완료`, `대체됨`을 구분합니다.
- 회의에서 합의됐더라도 필요한 구현과 검증을 마치지 않은 결정은 현재 구현 기준으로 간주하지 않습니다.
- 승인 범위를 벗어난 변경과 기존 사용자 변경을 건드리지 않습니다.

## 4. AI 작업 원칙

- 팀원이 역할을 한 문장으로 설명하지 못하는 계층을 만들지 않습니다.
- 첫 실제 파일 없이 미래용 하위 폴더를 만들지 않습니다.
- 새 파일의 입력, 출력과 사용자를 먼저 확인합니다.
- 실제 중복이 생기기 전에 범용 `common`, `utils`, Factory와 추상 인터페이스를 만들지 않습니다.
- 공통 데이터 상태, 라벨, 시간 형식과 입력·출력 계약을 임의로 변경하지 않습니다.
- 담당자의 내부 구현을 대신 결정해야 할 때는 공통 경계에 영향이 있는지 먼저 확인합니다.

## 5. 기본 뼈대 단계 제한

별도 요청 전까지 만들지 않습니다.

- Python 실행 파일과 임의 예제 코드
- Flask 애플리케이션과 route
- 담당자 간 전달 객체(DTO)·저장 및 조회·서비스 구현
- DB 연결 코드와 SQL
- 크롤링·모델·심리지수·LLM 구현
- 가짜 데이터와 샘플 JSON
- 모델 가중치와 체크포인트
- GitHub Actions와 Issue 템플릿
- Docker 및 Node.js 설정

실제로 수집된 댓글 일부를 사용한 수직 통합 테스트는 가짜 샘플 생성과 다릅니다. 사용자가 구현·검증을 요청하면 실제 데이터와 합의된 계약으로 수행할 수 있습니다.

## 6. 보안

- `.env`, API Key, DB 계정, 개인정보와 인증정보를 출력하거나 Git에 추가하지 않습니다.
- 실제 데이터와 모델 파일의 위치·권한·버전을 임의로 정하지 않습니다.
- 민감정보 노출이 의심되면 작업을 멈추고 영향 범위를 보고합니다.

## 7. 완료 보고

- 변경 파일과 이유를 보고합니다.
- 실행·테스트·검증 결과를 보고합니다.
- 검증하지 못한 항목과 후속 결정을 구분합니다.
- 공통 경계 변경 시 재라벨·재학습·재추론·재집계·DB·API 영향 여부를 명시합니다.

## 8. 프로젝트 문서 권한과 최신화

- `README.md`, `AGENTS.md`, `docs/*.md`는 팀장의 명시적인 요청이 있을 때만 수정합니다.
- 구현 요청만으로 프로젝트 문서 수정까지 승인된 것으로 간주하지 않습니다.
- 문서 변경이 필요하면 직접 수정하지 않고 변경 이유와 영향을 팀장에게 보고합니다.
- 팀장이 “`develop`의 최신 문서를 반영하라”고 요청하면 현재 작업 브랜치에서 `git fetch origin` 후 `git merge origin/develop -m "merge: develop 문서 최신화 반영"`을 실행합니다.
- 미커밋 변경이 있으면 임의로 커밋하거나 스태시하지 않고 먼저 상태를 보고합니다.
- 병합 충돌이 발생하면 상대 변경을 임의로 삭제하지 않고 팀장에게 보고합니다.
