## 1. 문서 목적

NAVER 댓글 검수 데이터를 반복 분석하면서 확인한 문제, 적용한 설정 변경, 변경 전후 결과를 추적하기 위한 자료입니다.

- 검수 대상 댓글: 78,422건
- 검수 파일:
  - `data/review/NAVER_token_review.csv`
  - `data/review/NAVER_feature_review.csv`
  - `data/review/NAVER_tfidf_score_review.csv`
- 현재 상태: 실험 결과 검수
- 주의: 정답 라벨을 사용한 모델 성능 비교가 아니므로 최종 설정 확정을 의미하지 않습니다.

## 2. 최초 검수에서 확인한 문제

### 감성 방향 표현 손실

기존 품사 필터가 `NN`, `VV`, `VA`, `SL`, `SN`만 허용하여 다음 표현이 다수 제거됐습니다.

- 부정: `안`, `못`, `않`, `못하`
- 강조: `진짜`, `너무`, `제발`, `절대`, `무조건`
- 감탄: `에휴`, `아오`, `헐`, `화이팅`

부정어가 제거되면서 서로 반대인 문장이 같은 토큰으로 합쳐지는 사례가 있었습니다.

| 원문 | 최초 토큰 |
|---|---|
| `어 안팔아~` | `팔` |
| `이거밖에 안올라?` | `오르` |
| `사진을 못올리게 만들어놨나?` | `사진 올리 만들` |

### 커뮤니티 표현 손실

`ㅋㅋ`, `ㅠㅠ`, `ㅜㅜ`, `ㅡㅡ`, `ㄷㄷ`처럼 게시판 감성을 나타내는 표현이 제거되어 빈 토큰 문서가 발생했습니다.

### 주요 투자 용어 분절

다음 투자·커뮤니티 용어가 여러 토큰으로 분리됐습니다.

- `손절` → `손 절`
- `추매` → `추 매`
- `주린이` → `주리 이`
- `상한가` → `상한 가`
- `개잡주` → `개 잡 주`

### TF-IDF 특성 과다

`MIN_DF=2` 상태에서 특성 46,482개 중 문서빈도 2인 특성이 19,983개였습니다. 전체 특성의 80.34%가 bigram이었고, 희귀 조합이 TF-IDF 상위에 과도하게 나타날 가능성이 있었습니다.

### 기타 문제

- 영문 대소문자 분리: `AI`, `Ai`, `ai` 등이 별도 특성으로 생성
- Kiwi 내부 공백 토큰 재분절: `젠슨 황`, `네이버 클라우드` 등이 `str.split`에서 다시 분리
- 고빈도 문법 토큰 유지: `거`, `것`, `때`, `듯`, `수`, `번`, `중`

## 3. 적용한 변경

### 전처리·토큰화

- 반복형 소셜 표현 정규화
  - `ㅋ{2,}` → `소셜웃음`
  - `[ㅠㅜ]{2,}` → `소셜울음`
  - `ㅡ{2,}` → `소셜짜증`
  - `ㄷ{2,}` → `소셜놀람`
- `XR` 품사 추가
- 허용표현 `INCLUDE_FORMS` 추가
  - `안`, `못`, `않`, `못하`
  - `진짜`, `너무`, `제발`, `절대`, `무조건`
  - `에휴`, `아오`, `헐`, `화이팅`, `가즈아`
- 불용어 추가
  - `거`, `것`, `때`, `듯`, `수`, `번`, `중`
- 사용자사전 확장
  - 기존: `외인`, `저점`, `고점`
  - 추가: `손절`, `익절`, `추매`, `주린이`, `상한가`, `개잡주`, `치지직`
- Kiwi 형태소 `form` 내부 공백을 `_`로 변환

### TF-IDF

- `NGRAM_RANGE=(1, 2)` 유지
- `MIN_DF=2` → `3`
- `SUBLINEAR_TF=False` → `True`
- `lowercase=False` → `True`
- `MAX_DF=0.95`, `MAX_FEATURES=None` 유지

## 8. 남은 검토사항

### `않`과 `-잖아`

`VX`의 `않`이 포함된 문서 1,263건 중 146건은 실제 부정이 아니라 `-잖아`, `-잖아요` 계열이었습니다.

- `오르잖아` → `오르 않`
- `가능하잖아` → `가능 않`
- `호재 확실하잖아` → `호재 확실 않`
- `재료가 좋잖아요?` → `재료 좋 않`

약 11.6%에서 강조·확인 표현이 부정처럼 보일 수 있습니다. `않` 전체를 제거하면 실제 부정도 손실되므로, 향후에는 원문 표면형이 `잖`인 경우만 제외하는 방식을 검토합니다.

### 빈 토큰 문서

3차 결과에도 빈 토큰 문서가 2,226건 남았습니다. 마침표·물음표만 있는 문서와 `와`, `영차`, 단독 자모 등으로 구성된 문서가 포함됩니다. 모든 문서를 억지로 보존하기보다 다른 종목에서도 같은 양상이 반복되는지 먼저 확인합니다.

### 문서와 구현 설정 정합성

현재 `pilos/analysis/vectorizer.py`는 `lowercase=True`이지만 `docs/DECISIONS.md`의 D-008에는 `lowercase=False`로 기록되어 있습니다. 다른 종목 비교 후 현재 값을 채택하면 기술 결정 문서의 대체 여부를 팀장이 판단해야 합니다.

## 9. 다음 검증 계획

현재 설정을 다른 종목에 동일하게 적용하여 NAVER 전용 최적화인지 일반적인 개선인지 확인합니다.

종목별 비교 항목은 다음과 같습니다.

- 빈 토큰 문서 비율
- `안`, `못`, `않`, `제발`, `너무` 반영 비율
- 소셜 토큰 비율
- 전체 특성 수와 bigram 비율
- 종목별 미등록어와 잘못 분절된 단어
- `-잖아 → 않` 발생 비율
- 동일 `tfidf_text` 중복 비율

모델 라벨이 준비되면 동일한 학습·검증 분할에서 Macro-F1과 클래스별 재현율을 비교하여 최종 설정을 결정합니다.
