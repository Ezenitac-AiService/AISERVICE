# 수급지수 선형 모델 실험 기록

> 상태: 최종 모델 선정·v4 전체 재학습·DB 추론 결과 적재 완료
>
> 데이터 종료일: 2026-07-24
>
> 목적: 발표와 서비스 후보 선택의 근거를 재현 가능한 코드와 표로 남긴다.

## 1. 모델이 표현하는 관계

현재 Dataset의 한 행은 `종목 × 거래일 × 수급 방향`의 일별 문서다.
같은 날의 댓글 토큰 TF-IDF와 같은 날의 수급지수를 연결하여 단어별
연관계수를 학습한다. 따라서 결과는 미래 수급 예측이나 인과효과가
아니라 **당일 댓글 표현과 당일 수급지수의 연관성**으로 해석한다.

발표와 화면에서는 `미래 예측 키워드`보다 `당일 수급 연관 키워드`,
`수급지수 기여도`라는 표현을 사용한다.

## 2. 워크포워드 실험

### 2.1 설계

- 검증 구간: 2026년 4월, 5월, 6월, 7월 1~24일
- 후보: Ridge 8개와 ElasticNet 32개
- 방향: Positive, Negative
- 총 평가: `40개 후보 × 2개 방향 × 4개 Fold = 320회`
- 검증 목적: 과거로 학습하여 이후 월을 맞히는 분포 변화 스트레스 확인

### 2.2 핵심 결과

#### Positive

| 후보 | 평균 검증 R² | 최저 R² | R² 표준편차 | 평균 학습 R² | 평균 비영(0이 아닌) 계수 | 계수 희소성 |
|---|---:|---:|---:|---:|---:|---:|
| Ridge, text only, alpha=1 | 0.0481 | -0.0274 | 0.0489 | 0.7211 | 17,047 | 0.0% |
| Ridge, text only, alpha=10 | 0.0419 | 0.0263 | 0.0115 | 0.2594 | 전체 | 0.0% |
| ElasticNet, text only, alpha=0.001, l1=0.1 | 0.0465 | 0.0322 | 0.0089 | 0.2253 | 284 | 98.3% |
| Ridge, text+댓글 수, alpha=1 | 0.0435 | -0.0394 | 0.0544 | 0.7218 | 전체 | 0.0% |

Positive의 ElasticNet 후보는 Ridge alpha=1과 평균 R² 차이가 작으면서
네 Fold가 모두 양수였고 약 98.3%의 계수를 제거했다. Ridge alpha=10도
모든 Fold가 양수여서 단순한 강한 L2 규제 대안으로 남겼다. 댓글 수를
추가한 현재 방식은 text only보다 평균·최저 R²와 변동성이 모두 나빴다.

#### Negative

| 후보 | 평균 검증 R² | 최저 R² | R² 표준편차 | 평균 학습 R² | 해석 |
|---|---:|---:|---:|---:|---|
| Ridge, text+댓글 수, alpha=1 | 0.0508 | 0.0159 | 0.0408 | 0.7287 | 평균 R² 1위 |
| Ridge, text only, alpha=1 | 0.0503 | 0.0247 | 0.0365 | 0.7284 | 댓글 수 없이 거의 동일, 최저값·변동성 우세 |
| ElasticNet, text+댓글 수, alpha=0.0001, l1=0.9 | 0.0381 | -0.0351 | 0.0475 | 0.4171 | 희소화 대안이나 Ridge보다 낮음 |

Negative에서 댓글 수 추가의 평균 R² 이득은 약 0.0005에 불과하고
최저 R², 표준편차와 예측 편향은 text only가 더 안정적이었다. 따라서
워크포워드만으로 댓글 수 특성의 견고한 효용을 확인했다고 보기 어렵다.

### 2.3 확인된 분포 변화

검증 월별 댓글 수 중앙값은 Positive에서 166 → 467 → 787 → 438,
Negative에서 228 → 231 → 301 → 116이었다. 특히 Positive는 초기
학습 구간과 최근 검증 구간의 활동량 차이가 커서 절대 댓글 수 특성이
월 변화의 대리변수로 작동할 위험이 있다.

## 3. 날짜 그룹 랜덤 검증

### 3.1 필요성

2026-08-12 발표 전에 충분한 신규 미래 구간을 확보할 수 없다. 또한
현재 모델의 주된 목적은 미래 방향 예측이 아니라 같은 날의 단어와
수급지수 관계를 서비스에서 설명하는 것이다. 따라서 워크포워드는
분포 변화 스트레스 검사로 유지하고, 보유 Dataset 내부의 일반화는
날짜 그룹 랜덤 검증으로 별도 확인한다.

### 3.2 설계

- 각 월의 고유 날짜 약 20%를 검증 날짜로 무작위 선택한다.
- 같은 날짜의 모든 종목은 훈련 또는 검증 한쪽에만 배치한다.
- Positive와 Negative는 같은 날짜 분할을 사용한다.
- 난수 시드 42, 43, 44, 45, 46의 다섯 분할을 반복한다.
- 워크포워드에서 의미가 있었던 방향별 세 후보만 재검증한다.
- 총 학습 횟수는 `2개 방향 × 3개 후보 × 5개 시드 = 30회`다.
- TF-IDF vocabulary, IDF와 댓글 수 Scaler는 각 Fold의 훈련 행으로만
  학습하여 검증 정보 누출을 막는다.

### 3.3 평가 후보

Positive:

1. Ridge text only, alpha=1
2. Ridge text only, alpha=10
3. ElasticNet text only, alpha=0.001, l1_ratio=0.1

Negative:

1. Ridge text only, alpha=1
2. Ridge text+댓글 수, alpha=1
3. ElasticNet text+댓글 수, alpha=0.0001, l1_ratio=0.9

### 3.4 결과

실제 DB 조회 데이터로 2026-08-03에 30회 학습을 실행했다. Positive는
총 2,055행 중 시드별 1,648~1,687행을 학습하고 368~407행을 검증했다.
Negative는 총 1,735행 중 1,353~1,392행을 학습하고 343~382행을
검증했다. 모든 후보의 다섯 검증 R²는 양수였다.

#### Positive 결과

| 후보 | 평균 검증 R² | 최저 R² | R² 표준편차 | 평균 학습 R² | 학습-검증 R² 격차 | 평균 비영 계수 | 희소성 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Ridge, text only, alpha=1 | **0.2068** | **0.1871** | 0.0172 | 0.7143 | 0.5075 | 21,242 | 0.0% |
| ElasticNet, text only, alpha=0.001, l1=0.1 | 0.1451 | 0.1299 | 0.0141 | 0.2153 | **0.0702** | 281 | 98.7% |
| Ridge, text only, alpha=10 | 0.1189 | 0.1061 | **0.0089** | 0.2442 | 0.1253 | 21,242 | 0.0% |

랜덤 날짜 검증의 성능 우선 후보는 Ridge text only alpha=1이다.
ElasticNet은 평균 281개 계수만 남기고 학습-검증 격차도 가장 작지만,
Ridge alpha=1보다 평균 검증 R²가 약 0.0617 낮다. Ridge alpha=10도
변동성은 작지만 평균 R²가 약 0.0879 낮다.

#### Negative 결과

| 후보 | 평균 검증 R² | 최저 R² | R² 표준편차 | 평균 학습 R² | 학습-검증 R² 격차 | 평균 비영 계수 | 희소성 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Ridge, text+댓글 수, alpha=1 | **0.2215** | **0.1831** | **0.0260** | 0.7248 | 0.5033 | 16,156 | 0.0% |
| Ridge, text only, alpha=1 | 0.2212 | 0.1826 | 0.0265 | 0.7246 | 0.5034 | 16,155 | 0.0% |
| ElasticNet, text+댓글 수, alpha=0.0001, l1=0.9 | 0.1816 | 0.1404 | 0.0263 | 0.4195 | **0.2378** | 190 | 98.8% |

댓글 수를 추가한 Ridge의 평균 R² 이득은 0.000227에 불과했다. 시드별
차이는 `+0.000337, +0.000141, +0.000546, -0.000967, +0.001079`로,
한 분할에서는 text only보다 나빴다. 평균 댓글 수 계수는 0.01494지만
성능 이득이 오차 수준이므로 댓글 수 특성의 견고한 효용으로 해석하지
않는다. 기능 단순성과 두 방향의 입력 계약 통일을 고려하면 Negative도
Ridge text only alpha=1을 우선 후보로 본다.

#### 워크포워드와 함께 보는 해석

Ridge text only alpha=1의 평균 R²는 워크포워드에서 Positive 0.0481,
Negative 0.0503이었지만 날짜 그룹 랜덤 검증에서는 각각 0.2068,
0.2212였다. 이 상승은 모델 자체가 새로 좋아진 결과가 아니라, 같은
전체 기간에서 월 분포를 섞어 검증했을 때 동시점 연관성이 더 잘
재현된다는 뜻이다. 반대로 시간 순서를 강제하면 댓글량·어휘·수급 분포
변화로 성능이 크게 떨어진다는 기존 진단도 유지된다.

따라서 발표에서는 다음 두 결과를 함께 제시한다.

- 날짜 그룹 랜덤 검증: 보유 Dataset 내부의 당일 수급 연관성 재현
- 워크포워드 검증: 시간 분포 변화에 대한 스트레스 테스트

랜덤 검증의 Ridge 학습-검증 R² 격차가 두 방향 모두 약 0.50이므로
과적합 위험이 사라진 것은 아니다. 검증 R²가 모든 시드에서 양수라는
사실과 높은 학습 R²를 함께 공개하고, 미래 예측 성능으로 확대 해석하지
않는다.

통계적 연관성이며 단어 하나의 인과효과가 아니다.

### 3.6 결론

1. 현재 서비스 성능 우선 후보는 두 방향 모두 Ridge text only,
   alpha=1이다.
2. 댓글 수 특성은 Negative에서 평균 R²를 0.000227만 높여 유지 근거가
   부족하며, Positive 워크포워드에서는 오히려 악화됐다.
3. ElasticNet은 약 190~281개 단어만 남기는 설명용 희소 모델 후보지만
   현재 shortlist에서는 Ridge보다 검증 R²가 낮다.
4. 발표에서는 날짜 그룹 랜덤 결과를 당일 연관성 검증으로 사용하고,
   워크포워드 결과를 시간 분포 변화 한계로 함께 제시한다.
5. 이 단계의 후보 비교 실행은 모델 파일과 DB 아티팩트를 생성하지
   않았으며, 최종 선정 후 별도 서비스 학습을 수행했다.

## 4. 산출물 계약

- `fold_results.csv`: 30회 학습의 날짜·표본·성능·편향·계수 진단
- `summary_results.csv`: 방향별 여섯 후보의 다섯 시드 집계
- `keyword_results.csv`: 평균 검증 문서에서 기존 디코더가 계산한
  양수·음수 기여도 상위 10개 키워드

키워드 contribution은 `검증 TF-IDF 평균 × 학습된 텍스트 계수`다.
한 시드에서 단순히 계수만 큰 단어가 아니라 실제 검증 문서에서 관측된
강도까지 반영한다.

## 5. 최종 서비스 모델 선정과 학습

### 5.1 선정 모델

2026-08-03에 Positive와 Negative 모두 다음 모델을 서비스 모델로
선정했다.

| 항목 | 최종값 |
|---|---|
| 모델 | Ridge Regression |
| 특성 | TF-IDF text only |
| alpha | 1.0 |
| ngram | unigram `(1, 1)` |
| `min_df` | 5 |
| `max_df` | 0.95 |
| `sublinear_tf` | True |
| 댓글 수 특성 | 사용하지 않음 |

Negative의 text+댓글 수 후보가 랜덤 검증 평균 R²를 0.000227 높였지만
분할 하나에서는 오히려 낮았고 Positive에서는 시간 검증 성능을
악화시켰다. 두 방향의 입력 계약을 통일하고 불안정한 날짜별 댓글량을
모델 특성에서 제거하기 위해 text only를 최종 선택했다.

### 5.2 공식 내부 검증 지표

서비스 학습기는 시드 42~46의 월별 층화 날짜 그룹 80:20 분할을
Positive와 Negative에 공통으로 적용한다. 매 분할에서 Vectorizer와
Ridge를 새로 학습하고 검증 지표만 평균한다. 다섯 임시 모델의 계수나
예측값을 평균하여 서비스 모델을 만들지 않는다.

| 방향 | 평균 검증 행 | MAE | RMSE | R² |
|---|---:|---:|---:|---:|
| Positive | 395 | 0.111898 | 0.139891 | 0.206797 |
| Negative | 355 | 0.104443 | 0.132580 | 0.221247 |

이 지표는 보유 기간 내부에서 당일 댓글 표현과 당일 수급지수의 관계가
얼마나 재현되는지를 나타낸다. 신규 미래 기간의 예측 성능으로 해석하지
않으며, 시간 분포 변화 한계는 워크포워드 결과와 함께 공개한다.

### 5.3 전체 Dataset 최종 재학습

검증 완료 후 평가용 임시 객체를 폐기하고 `2025-01-02~2026-07-24`
전체 Dataset으로 Vectorizer와 Ridge를 처음부터 다시 학습했다.

| 방향 | 전체 학습 행 | 전체학습 MAE | 전체학습 RMSE | 전체학습 R² |
|---|---:|---:|---:|---:|
| Positive | 2,055 | 0.067961 | 0.085746 | 0.712549 |
| Negative | 1,735 | 0.063998 | 0.080481 | 0.723438 |

최종 객체는 모델 bundle 스키마 2, 모델 버전 4로 저장했다.

| 방향 | 파일 | DB artifact_id |
|---|---|---:|
| Positive | `artifacts/ridge_supply_positive_text_only_v4.pkl` | 7 |
| Negative | `artifacts/ridge_supply_negative_text_only_v4.pkl` | 8 |

DB의 `artifact_type`은 `ridge_text_grouped_random_bundle`이다.
`validation_start_date=2025-01-02`는 시간 검증 시작일이 아니라 랜덤
검증에 참여할 수 있었던 Dataset 기간의 시작일이다.

## 6. 서비스 추론과 DB 적재

### 6.1 실행 흐름

`pilos.jobs.predict_model`은 다음 순서로 실행된다.

1. DB `artifacts`에서 방향별 정확한 모델 버전 4를 조회한다.
2. 저장소 상대 경로를 검증하고 신뢰된 pickle bundle을 불러온다.
3. DB 행과 bundle의 모델명·방향·버전·토크나이저·Dataset 기간을
   교차검증한다.
4. `daily_document`와 `supply_demand`를 종목·날짜로 INNER JOIN하여
   수급 데이터가 존재하는 거래일 문서만 조회한다.
5. Positive와 Negative 모델로 같은 일별문서를 각각 추론한다.
6. 예측점수와 단어별 contribution 상위 10개를 계산한다.
7. 두 방향이 모두 성공한 뒤 `sentiment_index_result`에 한 트랜잭션으로
   신규 결과만 적재한다.

### 6.2 실제 적재 검증

`2026-07-25~2026-07-31`을 요청 범위로 실행했다. 주말을 제외한 실제
거래일 범위는 `2026-07-27~2026-07-31`이었다.

| 방향 | artifact_id | 일별문서 | 신규 적재 | 품질 상태 |
|---|---:|---:|---:|---|
| Positive | 7 | 28 | 28 | ready 28 |
| Negative | 8 | 28 | 28 | ready 28 |
| 합계 | - | - | 56 | insufficient 0 |

동일 명령을 다시 실행했을 때 신규 0건, 기존 결과 제외 56건으로 확인돼
`(daily_document_id, artifact_id)` 유일성이 유지됐다. 기존 결과를
UPDATE하거나 Upsert하지 않는다.

text-only 모델이므로 `comment_count_contribution`은 0.0으로 저장한다.
전체 56행에서 다음 식의 최대 수치 오차는 약 `1.94e-16`이었다.

```text
supply_demand_association_score
= intercept + text_score + comment_count_contribution
```

키워드 JSON에는 `rank`, `word`, `tfidf`, `coefficient`, `contribution`을
저장한다. 이 정보는 화면의 주요 기여 표현뿐 아니라 LLM 보고서가
예측지수의 방향과 근거 단어를 설명하는 입력으로 사용할 수 있다.

## 7. 검증된 실행 명령

저장소 루트에서 다음 명령을 사용한다.

```powershell
uv run python -m pilos.jobs.train_model
uv run python -m pilos.jobs.predict_model
```

학습 명령은 같은 모델 버전의 DB 행이나 파일을 덮어쓰지 않는다. 추론
명령도 같은 일별문서·아티팩트 결과를 덮어쓰지 않고 기존 결과로
분류한다.

## 8. 한계와 다음 결정

- 랜덤 검증은 보유 Dataset 내부의 동시점 연관성 재현을 평가하며,
  미래 시점 예측 성능을 증명하지 않는다.
- 같은 날짜 그룹 누출은 막지만 종목 고유 표현의 반복은 남아 있다.
- 랜덤 검증의 학습-검증 R² 격차가 크므로 과적합 위험은 남아 있다.
- 과거 날짜 백필과 발표 이후 실제 미래 구간이 쌓이면 시간 검증을 다시
  수행하고 모델 버전을 올려 비교한다.
- 모델 범위는 학습, 파일·아티팩트 등록, 거래일 일별문서 추론과 결과 DB
  적재까지다. 서비스에서는 이 v4 결과가 Flask 조회·v13 보고서·RAG 기반
  질의응답과 최상위 자동화에 연결돼 있다.
- 모델 재학습은 주기 운영 파이프라인에 포함하지 않는다. 새로운 실제 기간을
  확보해 v5 후보를 검증할 때 별도 실험·등록·calibration 절차로 진행한다.
